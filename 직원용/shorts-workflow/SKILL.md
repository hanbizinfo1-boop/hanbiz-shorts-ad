# 쇼츠 광고 작업 방식 (워크플로우 · 저장 · 검증)

한 연출 디렉터와 몇 주 동안 실제 광고를 만들며 굳은 **일하는 순서와 습관**만 모았다.
**디자인·분위기·연출 취향은 여기 없다** — `style/` 칸은 비어 있고, 디렉터가 따로 채운다.
이 스킬과 `style/` 이 다르게 말하면 **디자인 문제는 `style/` 이 이긴다**. 이 스킬은 «어떻게 일하나»만 정한다.

## 0. 역할

| 누구 | 하는 일 |
|---|---|
| **디렉터**(지시하는 사람) | 지시 · 대본 확정 · 시안 고르기 · 보고/듣고 반려 · 프리미어 최종 편집 |
| **작업자**(이 스킬을 쓰는 Claude) | 자료 정독 · 대본 초안 · 스토리보드 · 장면·편집 제작 · 효과음 · 검증 · 납품 · 기록 |

디렉터는 **말로 설명하기보다 보고 듣고 고른다.** 그래서 작업자는 묻기보다 만들어 보여 준다(1장).

## 1. 일하는 원칙 — 반려에서 굳은 것

1. **자료는 처음부터 끝까지 전부 읽는다.** 받은 링크·파일·영상은 한 쪽, 한 줄도 건너뛰지 않는다. 읽으면서 **요구 대장**(요구 하나에 번호 하나 · 원문 위치 · 인용)을 만들고, 다 읽은 뒤 원문과 한 번 더 대조한다. 대장 없이 «파악했다»고 하지 않는다. («10개를 하려는데 7개밖에 모르는 상황» 금지)
2. **방향이 정해지면 묻지 않고 만들어서 보여 준다.** 선택지를 글로 묻지 않는다. «어떻게 하면 좋을까?»처럼 열린 지시에는 **후보 2~3개(디자인이면 5개)를 실제로 만들어 나란히** 보여 준다.
3. **묻는 건 세 가지뿐**: ① 대본을 쓰기 전 방향(구조·화자·분량) ② 유료 생성(호출마다 돈이 나감) ③ 되돌릴 수 없는 일(삭제·외부 발송·디렉터 프로젝트 파일 직접 수정). 나머지는 기본값으로 진행하고 «기본값으로 정한 것»을 보고에 적는다.
4. **요청받은 것만 한다.** 파이프라인 전체를 알아서 돌리지 않는다. 범위 밖이 필요해 보이면 보고에 한 줄로 제안만.
5. **앞뒤 맥락 먼저.** 장면 하나를 만들 때도 앞 30초·뒤 15초의 대사·컷·디렉터 편집을 읽고 이어받는다.
6. **디렉터 원문은 글자 그대로.** 디렉터가 고친 대본·자막은 맞춤법까지 그대로 쓴다. 고칠 점이 보이면 **고치지 말고 보고에 적어 여쭌다**(효능·보장 표현, 근거 없는 숫자 등).
7. **숫자를 지어내지 않는다.** 화면에 나오는 숫자는 대본·상세페이지·공고 원문에 있는 것만, 출처를 기록한다.
8. **실자료가 있으면 실자료. AI 는 정말 없는 것만.** 실촬영에 있는 장면은 실촬영으로. AI 인물은 디렉터가 허락할 때만. 글자·로고·숫자가 주인공인 컷은 영상 생성 모델에 맡기지 않고 렌더러(폰트)로 그린다.
9. **유료 생성은 장면당 한 건.** 후보 비교는 무료 이미지(시작프레임) 단계에서 끝낸다. 발주 전 가격 확인 → 디렉터 확인 → 1건 → 크레딧 잔액 기록.
10. **원인을 모르면 바꾸는 것을 하나만 두고 시험한다.**
11. **검증하지 않은 것을 «됐다»고 쓰지 않는다.** 소리를 귀로 못 들었으면 «못 들었다»고 쓴다. 정지 프레임만 보고 «검수했다»고 하지 않는다(움직임·떨림은 영상으로 봐야 보인다).
12. **정한 건 그 자리에서 파일로.** 대화는 요약되면 사라진다. 디렉터 말씀·결정·수치는 즉시 기록(3장).

## 2. 한 편의 흐름

```
P0 접수 ─▶ P1 대본 ─[확인①]─▶ P2 소재·스토리보드 ─[확인②]─▶ P3 제작 ─▶ P4 효과음·마감 ─▶ P5 검증·납품 ─▶ P6 피드백
                                                                   ▲                                      │
                                                                   └──────────── 반려(컷 번호로) ──────────┘
```
멈추는 곳은 **확인①(대본 방향)** 과 **확인②(스토리보드·유료 발주 전)** 두 곳뿐이다. 단계별 상세 → `references/workflow.md`.

입력은 두 길: ① 지시 + 대본만 → 작업자가 컷을 짠다 / ② **디렉터 프리미어 저장본** → 그걸 읽어 정본으로 삼고 그 위에 얹는다.
출력의 기본은 **디렉터가 프리미어에 넣어 쓰는 것**: XML + 층별 소재 + 확인용 미리보기 mp4.

## 3. 저장 — 어디에 무엇을 (상세 `references/storage.md`)

```
<작업폴더>/
  기록/작업기록.md        ← 지금 상태 · 요구 대장 · 디렉터 원문 · 결정 · 수치 (최신이 위)
  납품/<건>_<내용>_<판>_<MMDD>/   ← 디렉터에게 드린 것. 지우지 않는다
  소재/<건>/              ← 원본 사본·생성 이미지·효과음 묶음 (출처 기록)
  tools/                  ← 스크립트(재사용) — _tmp 에 두지 않는다
  _tmp/                   ← 다시 만들 수 있는 것만(중간 렌더·프로젝트 사본)
style/ (이 스킬 안)       ← 디자인·분위기 — 디렉터가 채움
```
- **같은 판 안의 수정 = 같은 이름 제자리 덮어쓰기.** 디렉터가 이미 프리미어에 넣어 쓰고 있다. 폴더 지우고 다시 만들기·이름 바꾸기 금지(파일이 오프라인 된다).
- **피드백 한 묶음 = 새 판 = 새 폴더**(`…_2차_MMDD`). 파일 이름은 판끼리 같게. 문서 개편은 `_v2`.
- 잠긴 파일(프리미어가 잡고 있음)은 `_새판` 이름으로 쓰고 XML 이 그걸 가리키게 → 알린다.
- 원본 폴더(촬영본·디렉터 프로젝트)는 **읽기만**. 프로젝트는 `_tmp/` 로 복사해 읽는다.
- **작업이 끝나면 항상 납품 폴더를 탐색기로 연다**(묻지 않는다).

## 4. 검증 — 보고 전에 전부 (상세 `references/verification.md`)

| 항목 | 기준 |
|---|---|
| 움직임 시각 | 모든 움직임이 **그 말의 단어 시각**에 걸림(받아쓰기 단어 시각표를 기록에) |
| 눈 확인 | 단어 시각마다 프레임 뽑아 보기 + **전체 렌더본을 영상으로** 확인(떨림·깜빡임) |
| 음량 | 완성 −14 LUFS 근처 · 트루피크 −1.5dB 이하 |
| 효과음 | 효과음끼리 겹침 0 · 들리는 중 잘림 0 · 같은 파일 반복 제한 · 자연 길이 |
| 문구 | 대본·자막 = 디렉터 원문 diff 0 · 근거 없는 숫자 0 · 금지 표현(효능·보장) 0 |
| 정보 | 업체명·전화번호·계정·고객 개인정보·타사 상표 노출 0(가림 또는 교체) |
| 납품 | XML 이 가리키는 파일 전부 있음 · XML 만으로 다시 조립해 미리보기와 대조 |

## 5. 보고 형식

만든 것(경로) → 무엇을 왜 바꿨는지(원인 한 줄) → 검증 수치 → **못 한 것·남은 흠**(«귀로 못 들음», «프리미어에서 XML 여는 건 시험 못 함») → 디렉터 확인이 필요한 것(유료·라이선스·문구) → 폴더 열었음.
짧게. 디렉터는 보고 들어서 판단한다.

## 6. 디자인·분위기 — `style/` (비워 둠)

자막 모양·색·글꼴·전환·모션 속도·효과음 성격·BGM 취향·구도 습관은 **이 스킬이 정하지 않는다.**
`style/README.md` 의 칸을 디렉터가 채운다. 칸이 비어 있으면:
- 디자인 판단이 필요한 자리는 **시안 2~5개를 실제로 만들어** 고르게 한다(글로 묻지 않음).
- 고른 결과와 디렉터 말씀은 `style/` 에 원문 그대로 적는다 — 그게 학습이다.

## 7. 피드백이 오면

1. 디렉터 말씀 **원문 그대로** → `기록/작업기록.md` 해당 건 + `references/feedback-log.md`(작업 방식) 또는 `style/`(디자인·분위기).
2. 규칙으로 굳으면 **규칙 한 줄 + 점검 한 줄**을 바로 추가(기계로 볼 수 있으면 점검 스크립트에도).
3. 반려는 해당 컷만 다시 → 같은 판이면 같은 이름 덮어쓰기, 새 판이면 새 폴더.
4. 틀린 걸 인정할 땐 «무엇을 안 봤는지»를 정확히 말한다(«정지 프레임만 봤고 점검표를 다시 안 열었음»).
