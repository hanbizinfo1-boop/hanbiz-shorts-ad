## 1. prproj 읽기

- **프리미어를 저장한 뒤에 읽는다.** 실행 중이면 메모리에만 있는 변경은 안 읽힌다. **자동저장본(`Adobe Premiere Pro Auto-Save\` 최신본)이 가장 최신**일 수 있다.
- **원본이 열려 있으니 반드시 사본을 `_tmp/prproj/` 로 떠서 읽는다**(읽기 전용).
- 도구 (모두 `tools/`):

| 도구 | 하는 일 |
|---|---|
| `read_prproj.py <사본.prproj> <시퀀스이름> <출력.json>` | 트랙 단위 전수: 클립 위치(t0,t1)·소스 인점(s0,s1)·이펙트(모션 비율/위치, 흐림, 볼륨 레벨 키프레임)·전환 이름·그래픽 텍스트·글꼴·자막(C 트랙) 텍스트. 같은 이름 시퀀스가 여럿이면(빈 껍데기가 뒤에 있을 수 있다) 아이템이 가장 많은 것을 쓴다 |
| `prproj_timeline.py <사본.prproj> <출력.json>` | 오디오/비디오 트랙 아이템의 시작·끝·소스 이름만 간단히 + 소재별 사용 횟수 |

- 콘솔 한글 때문에 `PYTHONIOENCODING=utf-8` 필수. ⚠ `python -I` 로 읽으면 PYTHONIOENCODING 이 무시돼 한글이 깨져 보인다(파일은 정상 UTF-8).
- 구조(실측): `AudioClipTrackItem / VideoClipTrackItem → ClipTrackItem → TrackItem(Start/End, 틱 1초=254016000000) + SubClip(ObjectRef) → SubClip.Name`. 자막: `CaptionDataClipTrackItem → BlockVector → Block → FormattedTextData(base64)`.
- **읽기 함정**:
  - 타임라인 **0초에서 시작하는 클립은 `<Start>` 태그가 아예 없다** → 없으면 0 (이것 때문에 첫 컷을 «삭제된 것»으로 잘못 읽은 적).
  - 참조가 `ObjectRef`(숫자)와 `ObjectURef`(UID) 두 가지로 섞여 있다 → 둘 다 따라간다.
  - `InPoint`/`OutPoint` 는 `AudioClip`·`VideoClip` 바로 밑이 아니라 그 안의 `<Clip>` 한 겹 안쪽.
  - 오디오 필터는 `AudioComponent` 한 겹 안쪽에 `Component`.
  - **볼륨 저장값: 0dB = 0.17783**(`sfx.db(v)`). 1.0 을 0dB 로 읽으면 «올리신 걸 내리셨다»고 거꾸로 읽는다(10-07 반려).
  - 사장님 클립 효과(흐림 등)는 새 클립에 안 따라온다.
  - 비디오 프레임 표기가 60fps 여도 원본이 두 프레임마다 같은 그림(실제 30fps)일 수 있다 — 녹화본은 가변 프레임이고 녹화 프로그램의 **소리 시계가 느려** 소리 기준으로 맞추면 틀린다(빡이사DB: 화면 기준 어긋남 곡선을 클립마다 적용, 가변 프레임은 30fps 고정본으로 바꿔 V1 에 사용).
- 읽은 뒤 «장면 구간 ± 앞 30초·뒤 15초»의 자막(C 트랙)과 사장님 편집(확대·컷)을 보고 기록에 «앞/뒤 맥락» 줄을 남긴다.

## 2. 컷 조각(SEGS) 계산 — 사장님 컷대로 목소리·녹화·사람을 이어 붙인다

장면 구간 안에 사장님이 자른 클립 조각이 여럿이다. 장면 도구는 조각마다 다음을 가진다:

```
SEGS = [(시퀀스 시작초, 시퀀스 끝초, V1 녹화 원본 안 시작초, V2·A1 사람 원본 안 시작초), …]   # 빡이사 06 예: (440.29, 444.01, 831.814, 833.783), …
```
1. `read_prproj.py` 결과에서 구간과 겹치는 V1(녹화)·V2(사람)·A1 클립을 뽑는다. `t0,t1` = 시퀀스 위치, `s0` = 원본 안 시작(구간 경계에서 잘린 클립이면 `s0 + (구간시작 − t0)`).
2. 조각 사이 시퀀스 공백이 있어도 각 조각의 `(시퀀스 시각 → 원본 시각)` 대응을 유지한다.
3. 목소리: `ae_scene.voice([(ta, tb, 사람 시작초)…], 사람영상)` — 조각대로 이어 붙인 소리. 단어 시각: `words.word_times(segs, src)` → 시퀀스 초.
4. 애펙 JSX 에서 녹화 레이어를 조각마다 `startTime = s(ta) − 원본시작 · inPoint = s(ta) · outPoint = s(tb)` 로 놓는다(`s(t)=t−T0`).
5. 장면 시작/끝이 클립 **가운데**면 그 시각에서 잘라 바꿔 끼운다(13·16·17). 컷 경계면 경계 그대로(양 끝 컷 경계: 09·10·18·19).
6. 사장님이 컷을 다시 손보면 시각이 어긋나므로 **저장본 시각을 기록**한다(예: «10-07 15:31 저장본»). 사람이 포함된 렌더는 «원본 컷 바뀌면 다시 렌더» 알림.

### 사장님 가로 시퀀스의 배치(빡이사DB, 참고 — 세로 쇼츠는 재서 채운다)
- 1920×1080 · 59.94fps. V1 녹화(1080p, 후킹 원본은 4K 50%) · V2 사람(싱크1시간) **30% 왼쪽 아래**(x 0.073 → 1511.9 이후 0.093) · V2 **전체화면 50%** 구간(사람 강조 구간) · A1 목소리 **+7dB**(943조각, 2개 +5dB) · A2~A4 효과음 · C1 자막(GmarketSansMedium).

## 3. 납품 XML — «얹을 것만»

- `tools/lec_xml.py`: `lec_xml.V_TRACK, A_TRACK`, `SEQ_W/SEQ_H`(세로 쇼츠는 1080×1920), `write(out_xml, seq_name, mov, dur_s, t0_s, sfx=[(시각초, wav)], fps, tag)`. XML 을 프리미어로 불러오면 트랙 번호가 그대로 살아 있어서, 복사해 사장님 시퀀스에 붙일 때 그 트랙 자리에 바로 앉는다. 앞 트랙은 빈 트랙으로 자리만 잡고, 효과음이 겹치면 다음 트랙으로 넘친다.
- 트랙 약속(가로 강의 장면): **장면 영상 = 사람이 안 들어 있고 녹화 자리를 바꿔 끼우면 V1, 사람이 포함된 렌더면 V3**(사장님 V2 PIP 를 덮음) · 효과음 A2~. 사장님 09-30 «다음부터 영상은 V3 음성은 A2».
- fps: 59.94 · 29.97 · 30 지원. 시퀀스 fps 를 틀리면 효과음 시각이 어긋난다 — 사장님 프로젝트에서 확인한 값을 쓴다(**세로 쇼츠 fps 는 첫 작업 때 확인**; 분양 쇼츠 장면은 29.97, 강의 시퀀스는 59.94).
- 납품 3종: `NN_이름_시작초~.mp4`(장면; 파일명에 시퀀스 시작초) · `NN_이름_효과음.xml` · `NN_이름_미리보기.mp4`(장면 + 사람 PIP + 목소리 + 효과음). 같은 이름 제자리 덮어쓰기.
- 사장님이 «AI 전환은 내가»라고 하면 빨려 드는 순간에서 끝낸 영상 + 시퀀스 시각에 맞춘 배치 XML(자막 아래 V1, 효과음 A2~).
- 여러 낱개 효과음을 나눠 놓으실 수 있게 번호 매긴 낱개로 낸다(`NN_<역할>.wav`).
- **작업이 끝나면 항상 납품 폴더를 탐색기로 연다**: `Start-Process explorer.exe "…\한비즈-쇼츠광고\납품"`.

## 9. 광고 구조 (대본·CTA) — T2 대본 단계(`workflow.md` P1)에서 쓴다

영상미 이전에 **말의 구조** 문제다. 분양 광고에서 광고주가 «이대로 나가면 DB 엄청 안 뽑힐 것»이라고 한 뒤 시장 레퍼런스를 대조해 얻은 것. 한비즈 쇼츠의 업종·사실은 건마다 다르므로 **구조만** 가져오고 숫자·혜택은 사실 확인 후에 쓴다.

**광고주 3차 피드백(분양1·분양2, 09-23 저녁) 원문 요지**
- 편집 자체는 부드럽고 나쁘지 않다. 속도감·내용 전반 괜찮다.
- «그런데 **이상하게 문의를 넣고 싶지 않다.**» · «여태 만든 광고 중 최악» · «이대로 나가면 DB 엄청 안 뽑힐 것».
- 추측: 장면 전환 부분 영상들이 너무 비슷해서? → 할 일: 레퍼런스 전체 탐색(스니핏 · 메타 광고 라이브러리 · 구글 광고 투명성 센터 · 유튜브 광고) → 반박하든 적용하든 레퍼런스와 대조해 보고.
- 관점: 영상 1건 처리가 아니라 **시장에서 다른 광고 CTR 을 제치고 문의를 가장 많이 받는** 기준. 무한제작 구조(기준 CTR·DB KPI 못 지키면 다시) → «다음에 또 이런 피드백이면 문제»(한 번에 확실하게).

**상위 광고 공통점 7가지** (메타 광고 라이브러리 «분양» 영상 84건 중 집행 104~162일 11편; 집행 일수가 길수록 성과가 난 광고로 본다. 18편은 프레임을 초 단위로 확인, **소리는 못 들었다**)
1. **훅 = 지역 + «돈» 숫자.** 총가격이 아니라 **초기 자금**(계약금 0원·500만원·5%). 단지명·브랜드로 시작한 광고는 0편.
2. **문의 장치를 3개 이상 겹친다** — 초기 자금 최소 · 선착순/마감 · 자격 완화(청약통장·전매·대출) · 옵션/사은품.
3. **정보를 일부러 남긴다** — «분양가표 신청» «댓글에 분양가» «가격은 마지막에». (정정 09-27: 가격을 다 말해도 110일 넘게 도는 광고가 있어 «가격 공개가 가장 큰 원인»은 **거둔다** — 남는 차이는 아래 «측정».)
4. **CTA 는 고정 + 버튼** — 번호를 전 구간 고정하거나 끝에 버튼 그래픽 + 손가락/화살표. 중간 «↓ 빨리 신청» 한 번 더.
5. **사람 얼굴 0편.** 상담사·진행자·AI 모델이 나온 광고는 전부 집행 8~65일.
6. **영상 재료는 오히려 단조롭다** — 모델하우스 워킹 **한 컷**을 끝까지 쓴 광고(12변형·116일). 공들인 영상미보다 **말의 구조**.
7. **1인칭 구어체**(«~거든요?» «얘들아»), 길이 32~57초.

**대조 판단 (분양1·2 → 레퍼런스)**: «장면 전환이 비슷해서»는 원인이 아니다(상위가 더 단조롭다 — 반박 유지). 부족한 것: 훅이 총가격(초기 자금 0회) · 문의 장치가 뒤(20초대)에 묻힘(레퍼런스는 7~15초) · **연락 보상 없음**(«더 알아보기» 눌러도 무엇을 받는지 없음) · CTA 가 끝 자막 1회뿐 · 장점 나열이 대본의 약 60%(브로셔 낭독; 상위는 돈·조건 50% 이상, 장점은 «없는 게 없어!» 한 줄) · 자막 33블록(레퍼런스 16~20) · 대상 호명이 CTA 앞에 없음.

**v3 구조 (사장님 검토용 적용안, 35초 안팎) — 슬롯으로 일반화**
원칙: **말의 절반을 돈·조건에**, 장점은 한 줄로 압축, **상세 가격표·잔여 목록은 신청해야 받게**, CTA 는 중간 1회 + 끝 버튼. 영상 소재는 그대로(재료가 아니라 말의 구조 문제).

| 초 | 역할 | 말 | 화면 |
|---|---|---|---|
| 0~3 | **훅** | «○○ ○○을, 계약금 ○○으로 잡는다고?» (지역 + 초기 자금 숫자) | 대표 장면 + 초대형 숫자 + 꼬리말(조건 한정) |
| 3~7 | **자격** | 자격 완화 2~3개를 한 문장(청약통장·실거주·상한제 등 사실인 것만) | ✓ 줄이 하나씩 찍히는 조건 카드 |
| 7~12 | **가격 앵커 + 희소** | 옆 시세와 비교, 한정 수량 | 막대 비교 + 한정 도장 |
| 12~14 | **중간 CTA** | «선착순이라 남은 ○○부터 확인하세요» | ↓ 화살표 + 한 줄 |
| 14~24 | **가치 압축** | 장점은 한 문장(세대수·조망·커뮤니티·교통·학군을 몰아서) | 1.5초씩 빠른 컷, 키워드 스티커 |
| 24~30 | **정보 남김** | «상세 가격표·잔여 목록은 신청하신 분께만 보내드려요» | 흐리게 처리한 표 + 자물쇠 |
| 30~35 | **CTA** | «아래 더 알아보기 누르고 ○○ 먼저 받아보세요» | 야경/대표 컷 + **버튼 + 손가락 탭** + 대표번호 |

- **훅은 3개로 A/B** — 본문 하나에 첫 3초만 바꿔 CTR 로 고른다: A 초기 자금 · B 시세 비교·희소 · C 자격 완화.
- 뺀 것: 시공사 수식(→ 브랜드 한 단어), 평형 나열, 커뮤니티 종류 나열, 자격 문의 전형(→ 신청 후 상담), 근거 없는 수식(«대표할»).
- **확인이 필요한 것(사장님·광고주) — 사실이 아니면 쓰지 않는다**: ① 초기 자금을 훅으로 써도 되는가(1차 정액·합계 조건) ② 신청자에게 가격표·잔여 목록을 실제로 보내 줄 수 있는가(랜딩·상담 흐름) ③ 혜택·사은품이 있는가 ④ 나레이션 녹음 방식(TTS 키는 저장소 밖).
- 표시 주의: 계획 단계 사업은 «※ 계획 단계» 작은 주석(사장님이 빼라 하면 사장님 결정), 한정 수량·선착순 조건은 사실만.

**쇼츠 레퍼런스 카피에서 얻은 CTA·구조 요소** (09-28)
- 상단(왼쪽 위) **대표번호 고정 배너** 전 구간(영상 깔에 맞는 배경판 — 석재 질감은 글자와 다퉈서 바탕색에 35%만 섞음). 끝 **«더 알아보기» 버튼 + 손가락/커서**, 중간에도 한 번.
- 2~3어절 자막이 가운데에 계속 바뀜, 큰 숫자(5%)·소품 쏟아짐, 체크리스트가 한 줄씩 쌓임, 검은 화면 빨간 글자는 한 번(단 사장님 «까만 화면 별로» 가 이후 우선 — 8장).
- **넣지 않은 것**: 가짜 «LIVE 시청자 수» 표시(시청자를 속이는 요소), 올빼미 마스코트.
- 맞춤 원칙: 녹음 대본에 목소리가 있는 소구만 화면에서 크게 강조한다. 사장님 메모에만 있고 목소리가 없는 소구는 넣지 않는다(원하면 화면 글자로 추가 가능).
