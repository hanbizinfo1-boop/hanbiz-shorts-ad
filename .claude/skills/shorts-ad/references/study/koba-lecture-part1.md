## 1. 한 줄 요약 — 이 영상에서 가져갈 것

**«영상은 비싼 가챠다 — 그래서 돈이 안 드는 단계(기획 문서·정지 이미지·저해상도 애니매틱)에서 구도·타이밍·스타일을 전부 확정하고, 확정한 컷만 영상 모델에 태워라.»** 우리 파이프라인과 결론이 같은 쪽이고(Codex 이미지 먼저 → 확인② → 유료 1건), 거기에 얹을 수 있는 것은 ① 수정 연쇄 금지(열화) ② 시간 구간별 영상 프롬프트 + 아이들링·네거티브 ③ 애니매틱 한 번 ④ 앵커 이미지·레퍼런스 ⑤ 용어집(카메라·샷·애니메이션 원칙) 이다. 강사의 «많이 뽑아서 고른다»는 방식 자체는 **우리 돈 규칙에 맞지 않아 버린다**(5장).

## 3. 방법 — 이 구간에서 «하라는 방식»을 단계로 풀면

이 구간에는 **도구 UI 에서 값을 넣는 시연이 없다**. 아래는 슬라이드·말에서 나온 방법을 순서로 정리한 것이다. 비용·시간은 **말·화면에 나온 것만** 쓴다.

### 3-3. 크레딧 낭비 줄이기 6항목(슬라이드 52장)

1. **생성 전 프롬프트 한 번 검수** — «오타, 모순된 지시, 불필요한 조건 확인. 특히 카메라, 움직임, 금지사항을 먼저 체크.» 화면 프롬프트(Dreamina 붙여넣기용 한글, 제목 «Animation (2D 벡터) — 빠른 등장 + 시원한 인사 + 빠른 퇴장 (수정본)»): «@Image1을 첫 키프레임이자 스타일 기준으로 사용한다. … 3D 금지, 사실적 질감·입체 그림자 금지. 움직임은 픽사식 슬로우 인·아웃을 기본으로 하되, 등장·인사·퇴장은 빠르고 탄력 있는 스냅 타이밍을 준다. … [0.0-0.7초] 시작 시 캐릭터는 화면에 없다(프레임 하단 밖). … 올라오는 끝에서 위로 크게 오버슈팅했다가 «탁!» 하고 스냅하듯 제자리에 꽂힌다. 안착 순간 … 강한 스쿼시 … 스트레치 … 후드·앞머리·파카 끈은 몸통보다 한 박자 늦게 … 따라온다(오프셋/팔로우스루). [0.7-3.8초] … 손을 살짝 뒤로 젖히는 빠른 예비동작(앤티시페이션) 후 … 큰 아크 …»(뒤는 화면에서 잘려 있다). → **시간 구간 + 애니메이션 원칙 용어 + «금지» 문장 + 첫 프레임 이미지 참조** 한 묶음이 한 클립 프롬프트의 구조.
2. **영상보다 이미지를 먼저 확정** — «스타일프레임 → 스토리보드 → 영상 순서로. 이미지 단계에서 구도와 디자인을 잡는 게 훨씬 저렴하다.» 화면: Maestro 25컷 스토리보드(1 지휘 뒷모습, 2 지휘봉 손, 3 눈, 4 주황 캐릭터, 5·6 주황 캐릭터 표정, 7 색 줄무늬, 8~14 군중, 15 파랑 표정, 16~18 지휘자 정면·눈, 19~21 구체·폭죽, 22~23 불꽃, 24 지휘봉, 25 «MAESTRO» 타이틀).
3. **저해상도로 테스트, 마지막에 고해상도** — «테스트는 480p → 최종 선택 컷만 고해상도·업스케일. 단, 작은 글자나 얼굴 디테일은 저해상도만 믿지 말 것.»
4. **애니매틱으로 타이밍부터 확인** — «스토리보드를 이어 붙여 컷 길이, 카메라, 전체 흐름을 검증. 확정된 컷만 Seedance 같은 영상 모델에 투입.» 말: 480p 로 영상 **60개 넘게 미리 편집**(프리미어; AI 가 이어 붙인 게 아님), 애니매틱 = 최종 결과를 예측하는 가이드 영상.
5. **영상 길이에 맞게 프롬프트 작성** — «5초 안에 너무 많은 액션을 넣지 않기. 한 클립 = 하나의 핵심 액션. 복잡하면 여러 Shot 으로.» 말: 5초에 컷 2개 정도가 적당, 10초에 6~7컷.
6. **잘 나온 결과는 Anchor 로 활용** — «매번 처음부터 생성하지 말고, 잘 나온 이미지·프레임을 기준으로. 새로 뽑기보다 수정해서 가챠 횟수를 줄이기.»

### 3-4. 열화 현상 대응(슬라이드 15~18장 + 말)

- 노이즈에서 배운 패턴으로 **매번 새로 만들기 때문에** 일관성이 없다 + 수정을 재생성으로 연쇄하면 **열화**(얼룩·번짐·귀 형태 붕괴, 도트 퍼짐; 2D·1080p 에서도 심함, 3D·디테일 많은 이미지는 덜 티남).
- 해법(말·슬라이드): ① 고품질 **원본(앵커)** 에서 필요한 부분만 수정 ② 수정 지시를 **한 번에 합쳐서** 처음부터 생성(«스케이트보드 타는 캐릭터, 배경은 없애고 책은 들고 있지 않고 신발색은 파란색») ③ 수정은 Nano Banana 처럼 부분 수정이 강한 모델에.
- 확인한 결과(`extra/1740.jpg`): 3단 연쇄 수정에서 구름 번짐·귀 형태 변화·도트가 점점 늘어난다.

### 3-5. 결과물에서 확인한 것

- Maestro: 약 40초(2:52~3:30, 스트리밍이라 정확한 프레임 레이트·화질은 판독 불가), 25컷 스토리보드 기준 장당 평균 약 1.5초(추정). 같은 지휘자·빨간 외눈 캐릭터·색색 소품 캐릭터가 접사와 와이드를 오가도 **형태·색·질감이 컷 사이에서 유지**(0.25초 시트로 확인) — 스타일프레임 앵커의 효과로 읽힘. 단 최종 화질은 스트림 압축으로 판정 못 함.
- MiniMax H3 키네틱 타이포: 영어 단어만, 단어마다 질감·배경·3D 사물이 달라짐. **한글 타이포 결과는 이 구간에 없다.**
- Seedance vs MiniMax: 같은 캐릭터 이미지(주황 큐브 캐릭터 + 검)로 비교했으나 화면 끊김으로 우열 판독 불가.

### 5-2. 가챠를 우리 규칙 안으로 옮기는 설계(가장 중요한 결정)

강의의 핵심 구조는 «**확률 게임이므로 많이 뽑고 잘 고른다 + 범위를 좁힌다**» 이다. 우리는 앞쪽 «많이 뽑는다»를 **무료 단계에 몰아 쓴다**:

1. **Codex 한 세션**에서 컷당 후보 N장(앵커 기반) → 설계자가 고름 → 사장님 확인②에서 최종.
2. 영상화 발주 전 **프롬프트 전문 읽기 + 구간별 시각 + 금지문 + 첫 프레임 참조 + 아이들링**(카드 1)으로 **유료 1건의 성공률**을 올림.
3. 받은 영상이 부적합하면? **원인을 하나만 바꿔 재발주하는 것은 «장면당 1건» 규칙을 넘는다** → 사장님께 사유(원인·바꿀 하나·예상 크레딧)를 적어 **승인받고** 한 건 더. 기본값 자동 재시도 없음. (이 규칙 해석은 사장님 영역 — 7장에 기록)
4. 영상으로 못 풀 것은 **코드/AE**(카드 6)로 빼서 유료 건수를 줄인다.

- **Maestro 의 실제 화질·프레임 레이트·사운드**: 라이브 스트림 압축·끊김 때문에 판독 불가(강의도 «패캠 페이지에서 보면 더 부드럽다»고 함). 완성본은 다른 담당(9jewtObTeRk). 소리는 **듣지 못했다**.
- **시연 클립의 실제 설정값**: 해상도·길이·시드·모델 버전(예: «Seedance 2.5»가 우리 MCP 의 어느 모델과 같은지)은 이 구간에 없다. 화면에 노드형 도구(입력 이미지 → 이미지 노드, «참고/표시/스타일/디렉터 스튜디오»)와 Dreamina 한글 프롬프트가 보이나, 어떤 서비스의 UI 인지는 화면에서 확정 못함(말: Higgsfield·Newtake 주력).
- **비용 숫자**: 말로 «약 30만원»(Maestro)·«300만원 쓰며 터득»·«강의 수강 시 10만원 정도»(채팅 답) 뿐이고 **화면에 크레딧 표는 없다**. 건당 비용은 모름.
- **Midjourney↔Codex 룩 품질 차이**, **Codex 의 한글 표현**: 시험하지 않았다(무료이므로 시안 1회로 확인 가능하나 이 작업 범위 밖).
- **MiniMax H3 한글 타이포**: 시연이 영어뿐이라 모른다. 한글은 코드 렌더로 간다는 결정은 «모른다»를 전제로 한 안전한 선택.
- **«장면당 유료 1건» 규칙의 예외(재발주) 승인 방식**: 사장님이 정할 일 — 5-2 의 3번은 제안.
- **슬라이드 05 팁(자연어/영어) ↔ 말(영어 변환) 불일치**: 어느 쪽이 강사의 실제 습관인지 확정 못함. 우리는 영어 자기완결형(ai-video 2장)을 유지하는 쪽으로 결정.
