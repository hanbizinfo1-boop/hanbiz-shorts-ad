## 3. 방법 (강의·제작 과정 영상)

**이 영상은 만드는 과정을 보여 주지 않는다.** 결과물(앞 6초) + 개념 설명 + 설치 명령만. 화면에 프롬프트 원문은 없다.

- 도구
  - **Remotion** — 화면 로고 «Remotion». 설치: `$ npx skills add remotion-dev/skills`(화면 글자 그대로, 00:19.8).
  - **HyperFrames** — 화면 로고 «HyperFrames». 설치: `$ npx skills add heygen-com/hyperframes`(00:20.0).
  - **코딩 에이전트** — «Claude Code · OpenAI Codex»(00:52.8). 간단한 건 «채팅»(클로드 채팅 + 코워크 통합, 00:55~01:04).
  - 자작 스킬 **`youtube-motion`**(00:16.5 · 00:33.0): 6단계 «기획(나+AI) → 리서치(팩트체크) → 윤문(AI 티 덜기) → 모션 그래픽(도구 스킬) → 검토(1차 AI · 최종 나) → 유튜브 발행».
  - 스킬 구조(00:24~28): `스킬 폴더` = `SKILL.md`(업무 매뉴얼) + `scripts/`(코드) + `도구·렌더 CLI` → «영상 만들고 렌더».
- 말로 확인되는 것: «이런 도구 스킬은 서비스가 직접 내놓기도 해서 명령어 한 줄이면 설치돼요. 안에 코드와 도구가 같이 들어 있어서 AI가 영상을 만들고 렌더하는 일까지예요.»(00:18.4) · «예약하면 전부 자동으로 돌릴 수도 있지만 최신 소식은 기획과 검수를 제가 직접 해요. 틀이 정해진 정기 콘텐츠라면 전자동도 괜찮고요.»(00:38.9) · «간단한 모션 그래픽은 채팅에서도 만들 수 있어요. 다만 이 영상처럼 내 컴퓨터의 도구를 계속 쓰는 긴 작업은 클로드 코드나 코덱스 같은 코딩 에이전트에서 만들어요.»(00:49.0) · «스킬을 직접 설치해서 쓰는 방법은 다음 영상에서 보여 드릴게요.»(01:09.5) → **설치·사용법은 다음 영상(미공개/미입수)**.
- 웹 검색으로 보충(2차 자료, 공식 문서로 재확인 필요): HyperFrames = HeyGen 오픈소스, **HTML 컴포지션 → 헤드리스 크롬이 프레임 캡처 → FFmpeg 로 mp4**, Apache-2.0, Node ≥ 22 · FFmpeg 필요, 스킬 `hyperframes`(작성·자막·TTS·전환) · `hyperframes-cli`(init·lint·preview·render) · `hyperframes-media`(TTS·받아쓰기·배경 제거). Remotion = React 로 영상을 코드로 만드는 도구, `npx skills add remotion-dev/skills`(Remotion 공식 문서에도 같은 명령), **회사 사용 라이선스 조건이 있다는 2차 자료가 있음(직원 4명 이상 유료라는 글 — 미확인, remotion.dev/license 확인 필요)**.
- 결과 확인: 앞 6초 모션 4개와 00:10.8~ 도식 전체가 **같은 파이프라인(HYPERFRAMES 표기)** 으로 만든 것으로 보인다 — 도식 구간에는 구석 표기가 없어 «같다»고 단정하지는 못한다.

## 4. 기법 카드

각 카드: 이름 · 무엇 · 왜 먹히나 · 시각(근거) · **우리 도구로 하는 법** · 난이도 · 한비즈 적용 예. «프레임 수»는 위 2장 방식(±2).

### 4-1. 단어 줄 쌓기 + 과대 착지 (모션 01)
- 무엇: 말하는 순서대로 큰 단어가 줄을 채워 쌓인다. 단어마다 **130~140% · 불투명 50~70% → 100% · 불투명 100%, 2~4프레임**, 줄 사이 ≈0.4초(12프레임). 앞 두 줄 흰색, 뒤 두 줄 주황(**색 = 의미 묶음**: «한번 만들면 / 계속 쓰다» 앞뒤 대비).
- 왜 먹히나: 큰 글자가 «꽂히는» 타격감 + 단어 단위라 읽는 속도가 말 속도에 맞음. 우리 팝(130→100, 0.216초 ≈ 6.5프레임)과 **같은 계통, 더 빠르고 불투명도를 같이 올린다**.
- 시각: 00:00.1~00:01.5 · 크기·간격은 2장.
- 우리 도구: AE JSX(`rf3_ae.HEAD` 의 `ez`/`keys`) 텍스트 레이어마다 scale 130→100 + opacity 60→100 을 4프레임에 `ez` 감속. 또는 `edit_render.cap_img` 로 줄 PNG → 그래픽 층(`edit_plan` `graphics`, anim `pop`).
- 난이도: 쉬움. 한비즈: 후킹 훅 «○○ 신축 / 초기 자금 / ○○만원»(말에 나온 숫자만) 쌓기 — 실제 문구는 사장님 대본 원문.

### 4-2. 색 반전 디졸브 (모션 01 → 02 경계, 00:01.8)
- 무엇: 바탕 남색→주황 + 글자색 반전을 **2~3프레임 선형 디졸브**로. «화면이 뒤집힘» 말과 맞추려 컷 대신 색만 뒤집음.
- 왜: 한 장면 안에서 «다음 단락»을 알리는 가장 싼 신호. 3색(남색·주황·흰) 안에서만 일어나 일관됨.
- 우리 도구: 영상 위에서는 바탕이 영상이라 **글자 패널 색**만 반전하거나, 단어 카드 0.4~0.9초를 영상 사이에 끼움(설계안 T6). AE: 솔리드 색 키프레임 2개 + 글자 fill 색 키프레임 2개(같은 프레임).
- 난이도: 쉬움. 한비즈: 단락 전환(문제→해결).

### 4-3. 한 단어 풀스크린 스왑 (모션 02, 00:01.9~00:04.3)
- 무엇: «기획 / 리서치 / 윤문 / 렌더» 한 단어씩 화면 전체. 배경 주황→흰→남색→주황으로 **하드컷**, 글자는 130~150%→100% 3~4프레임. 길이 0.90 / 0.43 / 0.47 / 0.67초.
- 왜: 단어 하나 = 한 컷, 속도감. 우리 레퍼런스 A(쌩초) «큰 단어로 화면 가득 + 0.5초마다 바탕 뒤집기»(`motion-graphics.md` 7장)와 같은 결 — **새 정보가 아니라 재확인**.
- 약점: 글자 크기가 일정해 2자 단어가 작고 허전. 우리는 **단어 폭을 화면 폭에 맞춰 키우는 규칙**(T2)으로 발전.
- 우리 도구: AE 컷 단위 컴프 4개 이어 붙이기 / `edit_render` 컷(kind image) 4장. 효과음은 컷마다가 아니라 묶음 하나(`sfx.md`).
- 한비즈: 단계·키워드 나열(«상담→계약→입주» 류 — 문구는 대본 원문).

### 4-4. 숫자 카운트업 + 막대 순차 성장 (모션 03, 00:04.3~00:05.9)
- 무엇: 숫자가 0에서 목표값까지 ease-out 으로 오르고(약 1.2초, 증가량이 지수로 줄어듦), 막대 6개가 왼쪽부터 순차로 자란다. 라벨 한 줄.
- 왜: «올라간다»는 말을 동작으로 증명. 도착값에서 멈춰 읽히는 시간이 생김(00:05.5~00:05.9 = 0.4초 정지).
- 약점: **숫자가 지어낸 더미** — 우리 규칙(숫자를 지어내지 않는다 · 말에 나온 숫자만, 시각 기록)과 충돌. 자릿수가 바뀔 때 가운데 정렬이라 폭이 흔들림(탭룰러 숫자 아님).
- 우리 도구: AE 표현식 `Math.round(...)` 슬라이더 + `ez` 감속(`rf3_ae`). 막대는 도형이라 **«도형 짜깁기 금지»(SKILL 4장)에 걸릴 수 있음 — 막대 대신 숫자만 + 단위 고정**(T7).
- 한비즈: 말에 나온 금액·면적·세대 수 — 그 말의 단어 시각에.

### 4-5. 윤곽선 드로우 → 글자 점등 → 자간 수렴 → 빛 스침 (모션 04 로고)
- 무엇: 주황 윤곽선이 약 9프레임에 둥근 사각형을 그림 → 글자가 3~4프레임에 켜짐 → 영문 태그라인이 **자간 넓음→보통으로 수렴하며 페이드 인(0.3초)** → **사선 빛 띠가 좌→우로 한 번 스침(약 4~6프레임)**.
- 왜: 도형이 먼저 «자리»를 만들고 글자가 채우는 순서라 시선이 정리됨. 자간 수렴은 «글자가 모여 자리 잡는» 느낌의 가장 싼 방법.
- 우리 도구: 로고 빛 스침은 기존 `b4_logo`(분양 통과 04, 미이식) 본보기와 동일 계통 — AE 마스크 스트로크 `Trim Paths` + 텍스트 Tracking 애니메이터 + 흰 평행사변형 매트 이동. `motion-graphics.md` 8장 «로고 빛 스침».
- 난이도: 중. 한비즈: **한비즈 CI 로고 엔딩 카드**(실제 로고 파일 필요 — 새로 그리지 않는다).

### 4-6. 윤곽 → 와이프 → 채움 카드 등장 (00:23.5~, 시그니처 모티프)
- 무엇: 카드마다 ① 윤곽선이 한 줄로 그려지고 ② 안이 회색으로 **좌→우 와이프** ③ 흰색으로 채워진 뒤 ④ 글자. 약 0.5초(15프레임). 한 편 내내 같은 문법(원칙 2·8).
- 우리 규칙과: «시그니처 모티프 하나»에는 부합, **«템플릿 같은 카드 나열»(금지 목록)** 에는 걸림 → 카드 도식은 정보 전달용 1~2장만, 말하는 사람/영상 위에서는 쓰지 않는다.

### 4-7. 형광펜 상자로 핵심어 하나만 (00:08.2 «스킬», 00:32.8 «youtube-motion», 00:10.8 «스킬»)
- 무엇: 한 문장에서 핵심어 하나에 주황 상자 + 남색 글자. 원칙 6과 같다.
- 우리: 자막 **강조어만 색**은 있고 «상자»는 없음 → 상자는 **헤드라인(자막이 아닌 글)** 에만, 자막은 색만(자막 스타일 이력 9: 단어별 색 강조는 그래픽 줄에서만).

### 4-8. 말-모션 1:1 대응 (00:00.3~00:09.6)
- 말 한 구절의 끝 시각에 모션이 바뀜(자막 교체 = 모션 전환 = 00:02.0·00:04.2·00:06.0). 우리 SKILL 3장 2번(**모든 움직임을 그 말이 나오는 단어 시각에**)과 같다 — 가져갈 건 이 대응을 **글 자체(자막)에도** 적용하는 것.

### 4-9. 구석 크롬 (HUD 잔글씨, 원칙 10)
- 좌상 채널명 · 우상 «MOTION 0N» · 좌하 날짜 · 우하 도구명. 정보가 아니라 «장면 번호 + 브랜딩 틀». 한 컷에 한 줄 6~7pt 급. 우리는 **업체명·번호를 넣지 않는다**(규칙 4) → 쓴다면 «01/04» 같은 진행 눈금만.

## 5. 설계자 관점 변형

### 5-0. 영상이 «하라는 방식» → 우리 파이프라인에서는 이렇게
| 영상의 방식 | 우리 방식(왜) |
|---|---|
| «말로 시키면 스킬이 모션 그래픽을 만든다» | 우리도 이미 **스킬 = SKILL.md + tools/**(`.claude/skills/shorts-ad`)다. 새로 배울 개념이 아니다. 차이는 렌더 엔진: 저쪽은 코드(HTML/React) → 프레임 캡처, 우리는 AE(`aerender`) 또는 PIL+ffmpeg(`edit_render`). **코드 렌더를 도입할지는 «AE 로 하기 어려운 글자 단위 모션이 많아질 때»의 선택지** |
| 6단계 `youtube-motion`(기획→리서치→윤문→모션→검토→발행) | 우리 `workflow.md` P0~P7과 같은 모양(설계자 직접·사장님 검수 두 지점). **«1차 AI·최종 나»** 가 우리 «설계자 검증 → 사장님 검수»와 대응 |
| 정기 콘텐츠는 전자동 | **금지에 가깝다** — 광고는 반려 이력이 매번 새 규칙을 만든다(SKILL 4장). 자동화는 «배치표 → 미리보기 렌더»까지만(`edit_render`), 연출 판단은 사람 |
| 모션 데모 = 단색 배경 | 우리는 **영상·사진 위**. 배경 대비·가독성 시험이 없는 시안이라 그대로 못 쓴다 — 아래 T5 |

### 5-1. 이 시안의 약점 진단 (사장님 «여기서 더 발전한 타이포그래피»)
1. **어휘가 하나** — 모든 등장이 «과대 착지» 한 가지. 쌓기·스왑·카운트·로고 4번 모두 같은 감각이라 타이포의 폭이 좁다.
2. **단위가 단어 블록뿐** — 글자(음절) 단위 움직임 없음, **굵기·크기 대비 없음**(전 줄 같은 크기, 강조는 색 하나).
3. **층이 둘이다** — 하단 자막(말)과 큰 모션 글(«한번 만들면 계속 쓰다», 말과 무관)이 서로 다른 내용을 보여 줘 시청자가 둘을 읽는다. 우리 규칙 4-2(중복·이중 자막 금지)와 반대 방향.
4. **자막 박스와 충돌**(00:01.5 «쓰다» ↔ 박스). 쌓기 레이아웃이 위에서 아래로만 자라 자막 안전영역을 안 지킴.
5. **배경이 남색·주황·흰 단색** — 영상·사진 위 가독성, 사물 뒤로 들어가는 깊이 등 «영상과 만나는 타이포»가 시험되지 않음.
6. **더미 숫자·이모지·카드 나열** — 숫자 지어내기(우리 규칙 위반), 🛠 🎬 이모지(금지 목록), 정보 카드 나열(템플릿 느낌).
7. **리듬이 빠르고 균일** — 단어 간격 ≈0.4초 고정(말 속도와 무관한 타이머). 우리는 **단어 시각에 건다**(말이 느리면 느리게).
8. 소리와의 정합 약함(봉우리-타격 33%) — 청음 안 함, 수치만.

### 5-2. 한국어 쇼츠 광고용 발전 설계안 8개
공통 전제: 자막 = 사장님 원문(규칙 4-1) · 강조어만 색, 말하는 순간 켜짐 · 팝 130→100 0.216초 또는 페이드+0.94→1.0 · 등장 4~8프레임 감속 · 바운스 금지 · 3색 · 새 요소 혼자 0.6초(글 단어는 «단어 시각 묶음») · 업체명 ○○ · 숫자는 말에 나온 것만. 세로 안전영역 수치는 **미확정**(SKILL 6장 ☐ — 첫 건에서 사장님 편집으로 잰다). 이 폴더 기본 `CAPTION_STYLE`(y 1150, size 66, max_w 960, stroke 9)은 확정 아님.

**T1. 말-시각 쌓기 + 재중앙 («쓰다가 자막에 닿는» 문제 해결)**
- 무엇: 줄이 말하는 시각마다 한 줄씩 들어오되, 새 줄이 들어오면 **블록 전체가 4~8프레임 감속으로 위로 재중앙**(블록 중심이 항상 안전영역 중심). 줄 수 4개 한계, 5번째부터는 첫 줄이 위로 사라짐.
- 규칙 정합: 단어 시각(원칙 4), 등장 4~8프레임(원칙 3), 자막과 겹침 검사(`ae_scene.check_boxes`)로 렌더 전 멈춤.
- 만드는 법: AE JSX — 줄 레이어마다 위치 키프레임 + `check_boxes`(자막 자리 입력). 편집 파이프라인이면 `cap_img` 줄 PNG 여러 장을 `graphics` 로 시각을 어긋나게.
- 프레임: 등장 130→100 + opacity 60→100 을 5프레임, 재중앙 이동 6프레임 ease-out. 난이도 중.

**T2. 폭 맞춤 키워드 카드 («기획» 이 작아 보이는 문제 해결)**
- 무엇: 한 단어 카드에서 **글자 높이가 아니라 단어 폭을 화면 폭의 70~85%로 맞춘다** — 2자 단어는 아주 크게, 5자 단어는 작게. 글자 수가 달라도 «꽉 찬» 인상이 일정.
- 규칙: 크기 대비(원칙 5)를 단어 단위로. 비교 장면이면 **쪽마다 색 하나**(빨강 vs 파랑)로 카드 두 장만(연달아 금지).
- 만드는 법: PIL — 단어 길이를 `ImageFont.getlength` 로 재서 size 를 `폭/길이` 로 계산(한글은 전각이라 길이가 글자 수에 비례 — 실측: Noto Sans KR VF 100px 에서 «계속 쓴다» 391px, 굵기 500·700·900 모두 동일). AE 는 텍스트 레이어 scale 을 같은 식으로.
- 프레임: 등장 6프레임. 난이도 쉬움. 한비즈: 단락 첫머리 핵심어 한 개.

**T3. 굵기 램프 — 말하는 순간 가는 글자가 굵어진다**
- 무엇: 강조어가 **Weight 300 → 900** 으로 8프레임 동안 굵어지며 동시에 색이 켜진다(색만 바뀌는 기존 «강조어만 색»을 굵기로 보강). 한글은 전각이라 **굵기가 바뀌어도 줄 폭이 변하지 않아**(위 실측) 레이아웃이 흔들리지 않음.
- 규칙: 강조어만 색(원칙 6 준수, 핵심어 하나). 바운스 없음.
- 만드는 법: ① PIL — `ImageFont.truetype(NotoSansKR-VF.ttf).set_variation_by_axes([w])` 로 프레임마다 굵기를 바꿔 알파 PNG 시퀀스(이 PC 에 `C:\Windows\Fonts\NotoSansKR-VF.ttf` 있음, Weight 축 100~900 확인) ② AE — 가변 폰트 축 애니메이션(AE 버전 지원은 **미검증**). Pretendard 는 이 PC 에 Bold·ExtraLight 만 있어(가변 아님) 중간 굵기 램프는 불가.
- 프레임: 8프레임. 난이도 중(시퀀스 렌더).

**T4. 음절 캐스케이드 — 한 줄이 파도처럼 켜진다**
- 무엇: 한 줄 자막/헤드라인의 **음절 하나하나가 2프레임 간격으로** y +24px → 0, 불투명 0 → 100%(각 6프레임 ease-out, 오버슈트 없음). 말의 한 어절(200~400ms) 안에서만.
- 한국어 현실: 한글 음절은 글자 한 개 = 블록 한 개라 **글자 단위 분해가 곧 음절 단위**(AE 텍스트 애니메이터 범위 선택기 «글자» 기준, `cap_img` 는 이미 글자별로 그림). **자모(초성·중성·종성) 분해는 폰트가 합성 글리프라 불가** — 대신 «초성 → 음절» 타자(자모 호환 글자로 먼저 보이다 교체)는 문자열 조합으로 가능(`bisa_ab_live` 의 타자와 같은 계통).
- 규칙: «글리치/흔들기는 한 편에 한 번» — 캐스케이드는 **한 편에 2~3곳**(가장 센 말), 매 줄 아님.
- 프레임: 음절당 6프레임 + 간격 2프레임(10자 줄 = 약 24프레임 ≈ 0.8초). 난이도 중.

**T5. 영상 위 깊이 타이포 — 사물 뒤로 들어가는 큰 글자** (Bos 의 «배경 단색» 약점)
- 무엇: 건물·소품·인물 **뒤**에 큰 글자(폭 90%)를 두고, 앞의 사물을 마스크로 오려 앞에 둠. **정지 이미지(Codex 시작프레임)+마스크 한 장+천천히 push-in(1.00→1.06)** 이면 프레임마다 로토가 필요 없다.
- 규칙: 한글은 AI 에 맡기지 않는다(PIL 합성), 단지·업체명은 ○○, 3색, 새 요소 0.6초 혼자. **AI 영상 위에는 쓰지 않는다**(프레임별 마스크 필요).
- 만드는 법: Codex 이미지 → 마스크는 알파 컷아웃(설치 없이는 수동 마스킹 또는 Codex 로 «배경만 단색» 별도 이미지) → AE 레이어 순서 [배경, 글자, 피사체] + 카메라 push-in. 마스크 자동화 도구(u2net 등)는 **설치하지 않았다·미검증**. 난이도 높음. 한비즈: 모델하우스 정면 컷 위 «○○».

**T6. 색 반전 카드 컷 — 핵심 주장 1줄(0.4~0.9초)**
- 무엇: 영상 사이에 **한 단어/한 줄 카드**를 끼움(남색→주황→흰 대신 우리 3색: 바탕·글·강조 하나). 섹션 끊을 때 **흰 플래시 2프레임**(`FLASH_FRAMES`)과 겹치지 않게 둘 중 하나만.
- 규칙: «같은 전환 연속 금지»(분양 범위) vs «시그니처 모티프»(후킹 범위) — **한비즈 쇼츠가 어느 쪽인지 미확인**(SKILL 5장). 카드는 한 편 2~3장, 연달아 두 장 금지(사이에 영상).
- 만드는 법: `edit_plan` cuts 에 kind image(PNG) 컷 추가 — 이미 지원. 난이도 쉬움.

**T7. 숫자 카운트업 + 단위 고정 + 도착 점멸**
- 무엇: 말에 나온 숫자만, 그 숫자가 나오는 **단어 시각에서 시작**해 ease-out 으로 도착(약 1초, 증가량 지수 감쇠). 숫자는 크게, **단위(만원·평·세대)는 작게 고정**, 도착 프레임에 강조색 1회 점멸(4프레임). 막대 도형은 쓰지 않는다.
- 규칙: 숫자 지어내기 금지·시각 기록 필수(SKILL 4장). 자릿수가 변해도 안 흔들리게 **오른쪽 정렬 또는 고정 폭 숫자**(탭룰러 — Pretendard 의 `tnum` 지원은 미확인, Noto Sans KR 도 미확인; PIL 에서는 숫자만 한 글자씩 같은 폭 칸에 그려 해결).
- 프레임: 카운트 30프레임 + 점멸 4프레임. 난이도 쉬움.

**T8. 자막-타이포 한 층 + 안전영역 (이중 층 해소)**
- 무엇: «말 자막»과 «모션 글»을 **한 층**으로 합친다 — 자막 줄 자체가 T1/T2/T4 의 타이포로 연출되고, 따로 하단 박스를 두지 않는다. 안전영역(자막 자리/사람 자리/자료 자리)은 한 번 정해 `check_boxes` 에 넣는다.
- 규칙: 4-2(중복 자막 금지), 자막 = 원문(4-1), 한 줄 규칙. 자막 스타일은 A/B/C 중 확정 전(`editing-premiere.md` 7장) — **사장님이 정한 쪽이 이긴다**.
- 난이도: 설계 결정(코드 아님). 사장님 확인 필요: «자막과 화면 글을 한 층으로 해도 되는가».

### 5-4. Remotion/코드 렌더가 우리 도구와 맞물리는 법
- **`node -v` → `v24.20.0`**(이 PC 에 Node 있음 — HyperFrames 요구 Node ≥ 22 충족, 2차 자료 기준). npm/npx·Chrome(`config.CHROME` 경로 설정만 봄, 실존 확인 안 함)·ffmpeg(이번 해부에 썼으니 동작은 함) 는 따로 확인하지 않았다. **아무것도 설치하지 않았다.**
- 맞물림 후보
  1. **클로드 디자인 HTML → `design_layers`** 는 이미 «HTML 을 크롬이 찍어 PNG»다. HyperFrames 는 «HTML 을 프레임마다 찍어 mp4»라 **같은 계통의 시간축 확장**. 우리가 하는 정지 레이어 + AE 키프레임을 HTML 애니메이션(CSS/GSAP)으로 대체하는 길인데, **글꼴 렌더가 PIL(Pretendard) ↔ 크롬(웹폰트)으로 달라져 자간이 안 맞을 수 있다**(미검증).
  2. 산출물을 **알파 PNG 시퀀스/알파 MOV** 로 뽑을 수 있으면 `edit_plan` 의 `graphics` 층(PNG 알파 또는 알파 MOV)에 그대로 얹힌다 — **HyperFrames/Remotion 이 알파 출력을 지원하는지는 미확인**(확인 전엔 AE 경로 유지).
  3. 글자 단위 모션(T3·T4)은 AE 텍스트 애니메이터가 이미 있어 **굳이 코드 렌더가 필요하진 않다**. 코드 렌더가 이기는 곳 = 데이터가 많이 바뀌는 반복 제작(수십 개 변주) — 한비즈 현 단계(건별 연출)엔 아직 아님.
  4. **라이선스**: HyperFrames Apache-2.0(2차), Remotion 은 회사 유료 조건 가능성(2차, 미확인) → 상업 광고 대행인 한비즈는 **Remotion 도입 전 라이선스 확인 필수**.
- 권고(설계자 결정 대기): 지금은 **AE JSX + PIL 유지**, 코드 렌더는 «시험 1건»만 후보 — 사장님 승인·설치 승인 후 HyperFrames 로 T4 한 줄을 알파로 뽑아 `graphics` 에 얹어 보기.

## 7. 못 본 것 · 불확실

- **소리**: 귀로 못 들었다. 효과음·BGM 유무·종류 모름(audio.csv 는 «휙/라이저»·«쿵/저역» 추정 분류뿐).
- **프롬프트 원문**: 영상에 없다(스킬 설치 명령 2줄 외에 AI 에게 한 말이 안 나옴). 이 쇼츠가 HyperFrames 로 만든 것인지는 «구석 표기»로 추정.
- 프레임 수는 2프레임 간격 샘플 기준 ±2프레임. 130~140% 같은 크기 비율도 눈으로 잰 값(정확한 키프레임은 알 수 없음). 첫 프레임(00:00.0~00:00.1)은 시트와 타일의 샘플 시각이 달라 한번 등장 시각이 0.0~0.13초 사이.
- 글꼴 이름(Pretendard 계열 / Montserrat 계열)은 **형태로 짐작**했다 — 확정 아님.
- HyperFrames·Remotion 의 현재 기능(알파 출력 등)·라이선스는 **웹 검색 2차 자료**: [HyperFrames GitHub](https://github.com/heygen-com/hyperframes) · [Remotion Skills 문서](https://www.remotion.dev/docs/ai/skills) · [HyperFrames 소개 글](https://silenceper.com/en/article/2026-05-02-hyperframes-html-video-rendering/). 공식 문서로 재확인 전엔 사실로 쓰지 않는다.
- T1~T8 은 **설계안이며 만들어 시험하지 않았다**(사장님 반응 없음 — 통과로 읽지 않는다).
- 세로 쇼츠 안전영역·자막 위치 확정 수치 없음(SKILL 6장 ☐).
