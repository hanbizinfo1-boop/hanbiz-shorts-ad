## 1. 한 줄 요약 — 이 영상에서 가져갈 것
1. **결과물 17종이 전부 «텍스트·UI·카드·로고·3D 소품을 코드로 움직인 것»** 으로 보인다(AI 영상 생성 흔적 거의 없음). 힉스필드 Vibe Motion 은 공식 설명상 **Anthropic 의 Claude 가 코드를 쓰고(Remotion 기반이라는 설명이 있으나 출처마다 다르다) 그것을 렌더하는 도구**다 → 우리가 Claude/Codex + AE/코드 렌더로 같은 «종류»를 만들 수 있다(5장).
2. 이 영상이 «한 영상에 여러 장면» 으로 보이는 이유는 **전환 방식 3가지(가로 슬라이드 · 원형 마스크 · 블러 디졸브)와 «프롬프트 알약 → 결과» 반복 틀** 때문이다. 알약(입력창)이 매번 장면을 열어 주고 결과가 알약에서 팽창한다.
3. **우리가 그대로 가져올 수 없는 것**: 영문 짧은 문구 중심, 장면마다 색·분위기가 다른 쇼케이스 구조(시그니처 모티프 없음), 실제 상표(맥도날드) 사용. 한비즈 한 편은 한 모티프로 간다(6장).

### 전체 판단(근거 묶음)
- **영상 생성 모델 흔적이 없다**: ① 글자(작은 영문 포함)가 모든 프레임에서 완벽 ② 가장자리가 벡터처럼 선명 ③ 카메라 이동 없음, 카드·판·소품이 기하학적으로 정확히 회전 ④ 뒷면 글자 거울 반전, 시계 숫자 일정 증가, 지구 질감이 안 일렁임. → 영상 생성이라면 글자가 번지고 도형이 흐물거렸을 것.
- **다만 «이미지 에셋»은 AI 생성으로 보이는 것이 많다**: 버거 재료, 로고 5종, 슬라이드 앞면 콜라주(고양이·석고상), 토리이. 그 부분은 영상이 아니라 **이미지 생성(→ 우리는 Codex)**.
- 따라서 Vibe Motion 의 일 = **(1) 프롬프트 해석 + 코드 생성(Claude) → (2) 이미지/입력 에셋 배치 → (3) 코드 렌더**. 우리는 (1) = 설계자(Opus) + Codex 코드, (2) = Codex 이미지·사장님 로고, (3) = AE 또는 자체 코드 렌더.

### «이정도 수준을 힉스필드 없이?» — 기능별 결론
| 기능 | 힉스필드 없이 | 근거 |
|---|---|---|
| 타이포(블러 인·타자·에코·줄 교체·기울기) | **가능, 품질 동등 이상**(AE 또는 코드) | 영상 결과가 전부 단순 보간 |
| UI 알약·카드·콜라주 | **가능**(클로드 디자인 → `design_layers` → AE) | 이미 통과 이력 있는 B 경로 |
| 로고 애니(슬라이드·마스크·디졸브·빛 스침) | **가능**(AE) | `04 로고 빛 스침` 선례 |
| 3D 판(카드 회전·카메라) | **가능**(AE 3D + 카메라, `rf3_ae` 선례) | 분양 3D 장표 장면 |
| 에셋 이미지(버거·로고시안·일러스트·사진) | **가능**(Codex, 글자 제외) | 구독 한도 안, 추가 과금 없음 |
| 3D 모델(파이·폰·지구) | **가능하나 수작업 증가**(Blender/CC Sphere/Codex 이미지 대체) | 한비즈에서 우선순위 낮음 |
| «프롬프트 한 줄 → 3초 생성 → 라이브 수정 캔버스» **편의 UX** | **우리에겐 없다** → 설계자가 Codex 로 코드를 만들고 렌더하는 파이프를 한 번 짓는 작업(`tools/` 신규)이 필요 | Higgsfield 는 이 UX 가 상품 |
- **한 번 지어야 할 것(미구현)**: ① HTML/Canvas → 프레임 번호 고정 캡처 렌더러(헤드리스 크롬은 `design_layers.py` 가 이미 씀; Node v24 있음) ② 또는 Remotion(라이선스: 직원 3명 이하 영리 법인 무료, 4명 이상 유료 — 한비즈 인원 확인). ①은 라이선스 없이 가능하나 개발 필요.
- **유료 도구는 불필요**: Kling 은 글자·UI 장면에 쓰지 않는다(글자 깨짐, 호출 과금, 장면당 1건 규칙). 힉스필드 구독도 필요 없다 — 구독을 «시안 비교용»으로 쓰자는 판단은 설계자 몫(CLAUDE.md 3번: 시험 삼아 넣지 않는다).

## 5. 설계자 관점 변형
영상이 «하라는 방식»: 영어 한 줄 프롬프트를 던지면 AI 가 알아서 장면을 만든다.
- 우리 파이프라인: **프롬프트가 아니라 «배치표 + 장면 스펙»이 입력**이다. 설계자(Opus)가 장면 스펙(글·시각·색 3개·모티프)을 쓰고 → 에셋(Codex 이미지·사장님 로고) → 렌더(AE/코드) → 효과음(`sfx.md`) → 점검(`rule_check`).
- 코드 렌더 쪽을 택하는 장면: 텍스트 중심·교체가 잦은 장면(키네틱 타이포, 타자, 자막 카드). AE 쪽: 로고·3D 판·사장님이 프리미어에서 후속 수정할 장면(레이어가 살아 있는 AE/XML).
- 순서: ① 한 장면을 코드 렌더 시험으로 **스모크**(1080×1920, 30fps, 3초) ② 글자 품질(한글 받침)·프레임 정확도 확인 ③ 통과하면 `tools/` 에 재사용 도구로 둠.
- 한비즈에 맞춘 소재 번역: 버거 → 서류·인증서·계약서·창고/공장 사진(Codex 연출 이미지, 업체 ○○) / 도쿄 시계 HUD → «심사 일정·접수 마감» 카운터 UI(숫자는 사장님 자료) / 발표 자료 카드 → 사업계획서 표지 3D 카드.
- 순서 규칙: 이미지는 유료 도구 전 Codex 로 전부(CLAUDE.md 3번) — 이 영상의 에셋 이미지는 모두 Codex 로 대체 가능한 종류.

## 7. 못 본 것 · 불확실
- **소리는 귀로 못 들었다.** 효과음이 있는지 판단 불가(나레이션 음절이 onset 으로 잡혀 audio.csv 가 무의미).
- Vibe Motion 이 Remotion 인지는 **미확정**(제3자 글). Claude 가 코드를 쓴다는 설명은 출시 기사·공식 블로그 검색 요약에서 확인했고 영상에는 안 나온다. 내 판단의 근거(글자·3D·거울 글씨)는 시각 증거라서 Remotion 여부와 무관하다.
- 버거 재료·로고 5종·토리이·슬라이드 앞면이 **생성 이미지인지 스톡·3D 렌더인지** 확정 못 함 — 이미지 에셋 출처는 낮음. 지구 텍스처(NASA 류 vs 생성)도 낮음.
- 3D 파이·폰 모형이 three.js 인지 렌더 소재인지 불명.
- 0.25초 간격 시트로 **0.1초 단위 전환·오버슈트**는 못 봤다(34.2–35.0 폰 회전은 프레임 사이가 큼).
- 홍보 영상이라 «3초 생성»이 실제 속도·품질을 보장하지 않는다(편집된 결과 모음일 수 있음). 실제 사용자 반응은 «일부는 AE 를 쓰겠다»는 혼합 평가라는 검색 요약뿐.
- 한비즈 로고·브랜드색·글꼴·직원 수(Remotion 라이선스)는 이 저장소에 없어 **우리 길의 «한비즈 적용»은 자리 표시**.
