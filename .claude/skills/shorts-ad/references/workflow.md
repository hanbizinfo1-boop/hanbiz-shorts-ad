# 한 편 전체 워크플로우 — 지시부터 완성본·피드백까지 (2026-10-08)

SKILL.md 3장은 **장면 하나**의 순서다. 이 문서는 그 위의 **쇼츠 한 편** 흐름이다 — 단계마다 «무엇을 읽고 · 무엇을 남기고 · 어디서 멈추나»만 적는다. 세부는 각 references 로 넘긴다.

**운영 방식(사장님 10-08 «아니 전체적으로 나는 너에게 지시를하면 t2 , t3를 네가 편집 연출등을 맡아서 하는 방향으로 갈거야»)**
사장님은 **지시**하고, 이쪽이 **편집·연출 전체**를 맡아 **완성본**까지 만든다. 주 유형은 T2·T3(2장). 사장님 프리미어 편집을 받아 위에 얹는 T1 은 주력이 아니다.
**프리미어와 주고받기(사장님 10-08 «그러면 프리미어로 내가 초안같이 잡아주는것도 염두에두자 네가 만드는걸 내가 프리미어에 넣어서 적용할게»)**
- 들어오는 길 둘: ① 지시 + 대본만 → 이쪽이 배치표를 쓴다 / ② **사장님 프리미어 초안**(컷만 잡은 것) → `read_prproj`·XML 읽기로 **배치표로 바꿔** 이어서 만든다(초안의 컷 길이·순서가 정본, 바꾸면 보고에 적는다).
- 나가는 길은 **프리미어에 넣어 쓰는 것이 기본**: 원본 참조 XML + 층별 소재(배경 컷 · 그래픽 알파 MOV · 자막 알파 MOV · 효과음 낱개) → 사장님이 컷을 밀거나 소재를 바꿔 적용. 미리보기 mp4 는 확인용.

→ 정본은 **사장님 지시 + 대본 원문**(초안이 있으면 초안의 컷)이다. 편집 결정(컷 리듬·전환·자막·효과음)도 이쪽이 내리고, 근거는 이식된 실측(`editing-premiere.md` 5장 · `motion-graphics.md` 8·9장)과 사장님 반려 이력이다.
**☐ 미확인** 표시는 첫 건에서 정해지면 이 문서와 `기록/작업기록.md` 에 바로 적는다.

## 0. 한눈에

```
지시 ─▶ P0 접수·범위 ─▶ P1 대본·콘티 ─[확인①]─▶ P2 소재·시안 ─[확인②]─▶
P3 컷 제작(컷마다 SKILL 3장 루프) ─▶ P4 조립 편집 ─▶ P5 효과음·마감 ─▶ P6 점검·납품 ─▶ P7 피드백 ─┐
                                              ▲                                              │
                                              └──────────────── 반려 ─────────────────────────┘
```
- **멈추는 곳은 두 군데만**: 확인①(대본·콘티 방향) · 확인②(시안·스토리보드 — 유료 발주 전 필수). 그 밖에는 **묻지 않고 만들어서 보여 드린다**(SKILL 4장).
- 되돌릴 수 없는 일(파일 삭제·외부 발송·유료 생성)만 따로 확인한다.
- 사장님께 보여 드리는 단위는 **한 편**(완성본 또는 확인용 초벌). 반려는 컷 번호로 받아 그 컷만 다시.

## 1. 단계별

### P0 접수·범위
- **자료 파악(10-08 사장님 «하나라도 빠짐없이»)**: 받은 링크·파일 전부 정독 → **요구 대장**(번호 · 요구 · 원문 위치 · 인용 · 산출물) → 원문과 재대조 → 사장님께 대장으로 확인받는다. 문서가 길면 나눠 읽되 구간 누락이 없게 «읽은 범위 표»(파일 · 쪽/시각 · 읽음)를 남긴다.
| 할 일 | 남기는 곳 |
|---|---|
| 지시 원문, 건 이름·목적·대상·길이, 원본 위치(경로만), **사용 허락 범위**(초상권·음원) | `기록/작업기록.md` «건 정보» |
| **편 유형**: T2 / T3 / 섞음(2장) | 같은 곳 |
| **범위 규칙**(SKILL 5장): 분양 캠페인 규칙 적용? «사장님 효과음만»? 편끼리 재사용 금지? 음성 1.15배? BGM? | 같은 곳 |
| 같은 캠페인 여러 편이면 «이미 쓴 소스 목록» 시작 | 같은 곳 |

### P1 대본·콘티 → **확인①**
- 대본은 사장님·고객 원문이 정본. 이쪽이 쓰면 **초안**으로 표시하고 근거 없는 문구·숫자를 넣지 않는다(checklist B 6-2). 첫 5초 후킹 요소 3개 이상(B 1-9).
- **대본을 쓰기 전**: 방향(구조·화자·분량·납품 형식)을 여쭙고 → 팩트체크(공고 원문 정독) → 대본. 말투·숫자·금지어는 `copy.md`, 납품 전 checklist F표 + `rule_check.py --copy`.
- **줄 × 화면 표(콘티)**: 줄마다 «그 말이 실제로 일어나는 자리» → 그림 하나(실자료 / Codex 이미지 / 애펙 그래픽 / AI 영상 / 블렌더). `design-paths.md` 0장 · `ai-video.md` 5장 1번. 같은 기법·비교 연출·같은 전환이 연달아 붙지 않게 표에서 미리 본다.
- 길이 어림: 음절 ÷ 5.5음절/초. 컷이 «감정 변화 / 액션 진전 / 압박 증대» 중 하나도 못 하면 지운다.
- 확인①에서 보여 드리는 것: 대본 + 콘티 표(줄 · 시각 어림 · 그림 · 한 줄 연출). 방향이 정해지면 그다음은 묻지 않는다.

### P2 소재·시안 → **확인②**
1. 목소리: 녹음본 또는 TTS(`editing-premiere.md` 5-5 — ☐ 이 PC 에 TTS 키 없음).
2. **대본 원문에 강제정렬** → 줄·단어 시각(받아쓰기 글자 쓰지 않음). 자막 싱크는 말 시작으로 당기고 0.05초 앞세움(`editing-premiere.md` 5-3).
3. **Codex 이미지 한 세션에 몰아서** — 시안·시작프레임·마스터피스·배경 질감·소품 전부(`design-paths.md` 2장, `ai-video.md` 2장 문장). 위임 `codex-luna`(병렬 금지).
4. 실자료(노선도·지도·평면도·로고)는 출처를 `소재/이미지-출처.md` 에.
5. 확인②에서 보여 드리는 것: 스토리보드(컷별 «다 나온 모습» 정지 화면) + AI 영상 컷의 시작프레임 후보. **사장님이 고른 것만** P3 에서 유료 1건.

### P3 컷 제작 — 컷마다 SKILL 3장 0~12 루프
- 컷 시작 때 `기록/작업기록.md` 장면 틀을 맨 위에 복사, **앞/뒤 맥락**(앞뒤 줄·앞 컷 소재) 줄부터.
- AI 영상 컷 → `ai-video.md` 6장 «영상화 직전 점검» → `get_cost` → 유료 1건 → 크레딧 누계 기록. 길이는 대사 구간에 맞춰 생성, 1배속.
- 애펙 그래픽 컷 → `motion-graphics.md`(6·8·9장) · `tools/ae_scene.py`. 블렌더 → `blender.md`.
- 컷 도구는 `tools/scenes/<건>_<NN>.py` — `tools/examples/` 에서 가장 가까운 본보기를 복사, 경로는 `config` 로.

### P4 조립 편집 (이쪽이 편집자)
- 배치표(컷 × 줄 × 시각 × 전환 × 자막 × 효과음 계기) 한 장이 편집의 정본. `rule_check.check_plan` 을 렌더 전에.
- 편집 문법 기본값 — 분양 쇼츠 세로 실측(`editing-premiere.md` 5장)에서 시작: 컷 평균 1.6~2.3초(긴 홀드·기본 박·연타 섞기) · 전환 0.25~0.35초, 7종 순환, 대부분 그냥 컷 · 섹션 바뀔 때만 흰 플래시 2프레임 · 자막 한 줄 + 팝 130→100% 0.216초(핵심 줄 120%) · 자료는 2초 이상, 다음 줄까지 끌고 감 · 배경은 정지, 글자·그래픽만 움직임.
- 이 값들은 **사장님 반려로 고친다** — 고친 값은 SKILL 6장 «재서 채울 칸» 과 작업기록 «세로 쇼츠 확정 수치» 에.
- **조립 도구(10-08 이식, 합성 소재 시험 통과 · 실제 건·프리미어 열기 미시험)**: 배치표 `tools/edit_plan.py`(스키마는 파일 맨 위, 본보기 `tools/examples/edit_plan_sample.json`, 사장님 초안 → `from_premiere`) → 미리보기 `tools/edit_render.py`(점검기 내장, ERROR 면 멈춤) → 프리미어 `tools/edit_xml.py`(`export` + `verify`). 시험 `python tools/edit_smoke.py`. 원본은 `D:\영상제작\도구\광고편집\sg_*`(09-29, 이어하기.md 91행 «오케이 이대로 XML 뽑아줘봐»).
  - 첫 건에서 확인할 것: ☐ 프리미어에서 XML 이 제대로 열리나(배속 Time Remap · Basic Motion 위치 · 마커) · ☐ 원본 fps 가 섞인 소스의 in/out(기본 `SRC_RATE="seq"`, 원본 sg 코드 주석 근거) · ☐ `.prproj` 초안 읽기 · ☐ 자막 기본 위치·크기(지금 sg 값 y=1150·66px — 쇼츠 확정 수치 아님).
  - 알고 둘 것: **전환(렌즈 블러 등)은 XML 에 못 담는다** → 미리보기에만 있고 XML 에는 시퀀스 마커로 표시. XML 쪽 음량은 리미터가 없어 마감 목표보다 작을 수 있다(`capped_db` 로 보고).
  - 원본 값이 섞여 건마다 배치표에 적는 것: 배속 1.12 / 1.15 · 마감 음량 −11(sg, 사장님 «소리가 너무 작은데») / −14(v5).
### P5 효과음·마감
- `sfx.md` 0~5장 · 11장. 범위 규칙(P0)대로 라이브러리. 역할마다 파일 이름 고정, 크기는 SKILL 2장. 밀도 기준 분양 완성본 초당 약 1.1개(`editing-premiere.md` 5-2).
- `rule_check.check_sfx` 통과 → 믹스. 음량 −14 LUFS 기준, 트루피크 −1.5dB 이하(ebur128). 귀로 못 들었으면 «못 들었다».

### P6 점검·납품
- `checklist.md` B표(+AI 컷은 C표)를 한 줄씩 → 결과를 보고에. 모아보기(`fps=2,scale=240:-1,tile=8x1`)로 전 구간 눈 확인.
- 납품: `납품/<건>/` 에 **프리미어 XML + `media/` 층별 소재**(정본) · 미리보기 mp4(확인용) · SRT. XML 은 XML 만으로 다시 조립해 미리보기와 대조한 뒤 드린다. 같은 이름 제자리 덮어쓰기(CLAUDE.md 9). 보고 형식 SKILL 10장. **보고 직전 `납품/` 탐색기로 연다.**

### P7 피드백
- 사장님 말씀 원문 → `기록/작업기록.md` + `feedback-log.md`, 효과음 반응 → `tools/data/예능효과음-실사용.json`, 통과/반려 → `motion-graphics.md` 8·9장.
- 규칙으로 굳으면 **규칙 한 줄(SKILL 4장) + 점검표 한 줄(checklist)** + 기계로 볼 수 있으면 `rule_check.py`.
- 반려 수정은 해당 컷만 P3/P4 로 돌아가 같은 이름에 덮어쓴다. 새 판이면 새 폴더.
