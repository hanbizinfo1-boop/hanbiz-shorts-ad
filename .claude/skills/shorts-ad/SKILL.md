# 한비즈 쇼츠 광고 제작

D:/영상제작 에서 사장님(광고 영상 연출가)과 쌓은 방식을 옮겨 온 스킬이다. 사실만 적었고 각 절 끝의 (원본: …)가 출처다. **여러 기법을 시도하는 곳**이라서, 정해진 하나가 아니라 «이 말이 실제로 일어나는 자리»에 맞는 기법을 고른다.
**이 스킬은 참조 문서가 크다 — 본문은 순서·규칙만, 세부는 `references/` 를 장면 종류에 맞게 열어서 읽는다.**

## 3. 작업 순서 (장면 하나)

0. **앞뒤 맥락 먼저** — 장면 구간만 보지 말고 **앞 30초·뒤 15초 자막과 사장님 편집(확대·컷)** 을 읽는다. 앞에서 보여 준 것(사장님 확대 위치·앞 장면 소재)을 이어받고 뒤 화면으로 자연스럽게 넘긴다. `기록/작업기록.md` 해당 장면에 «앞/뒤 맥락» 줄을 적고 시작한다. (프리미어 읽기: `references/editing-premiere.md` 1~2장)
1. **구도 결정** — «그 말이 실제로 일어나는 자리»(0-1). 설정·버튼 → 실제 설정 화면에 값을 넣는 느낌 / 개념 비교 → 비교 판(연달아 금지) / 과정·알고리즘 → 의인화·모션 / 보는 사람 시점 → 휴대폰 / 일상 상황 → 2D 애니 / 현실 공간·사람 → AI 영상. 직전 통과 틀을 복붙하지 않는다.
2. **단어 시각** — 그 구간 말을 사장님 컷 조각대로 이어 붙여 faster-whisper 단어 단위로 뽑는다: `python tools/words.py --src <사람영상> --seg 시작,끝,원본시작 … --out _tmp/<건>/words.txt` (CPU int8 medium). 장면의 **모든 움직임을 그 말이 나오는 단어 시각에** 건다. 받아쓰기 오인식(예: «뒷광고는» = «다른 광고는»)은 기록에 같이 적는다. 자막 글은 받아쓰기가 아니라 사장님 타임라인·대본 원문.
3. **화면 확인** — 그 시각 프레임을 뽑아 사람 위치·빈 벽·벽 글씨를 본다(0.25초 간격 프레임이 손짓·표정 시각을 찾는 데 쓰였다).
4. **시안(필요할 때)** — «시안 추천해봐» 하시면 3안을 ASCII 미리보기와 함께 묻고 추천안을 첫 번째에. **방향이 정해지면 그다음은 묻지 않고 만들어서 보여 드린다.** 스토리보드(장면별 «다 나온 모습» 정지 화면)를 먼저 보여 드리고 고친 뒤 움직인다(B 경로 아트보드가 이것).
5. **그림 만들기 — 길 고르기** (`design-paths.md`):
   A Codex 이미지(사진·마스터피스·2D 플랫·마스코트) / B 클로드 디자인 캔버스 → `design_layers.py` 레이어 / 녹화 화면 재현 / 실제 로고·국기(위키미디어, 출처 기록) / AI 영상(`ai-video.md`: Codex 시작프레임 **전부 먼저** → 사장님 확인 → 유료 1건) / 블렌더 프리비즈(`blender.md`). 이미지는 **Codex 가 먼저** — Kling·힉스필드는 호출마다 과금된다.
6. **조각 → 겹침 검사 → 애펙** (`motion-graphics.md`, `tools/ae_scene.py`): PIL 조각 PNG(투명, 제자리) → `check_boxes`(요소끼리·사람·자막·판 밖·화면 밖 — 걸리면 렌더 전에 멈춘다) → JSX(ASCII) → `AfterFX -r`(감시) → `aerender` → mp4. 등장은 `eo`(빠르게 들어와 감속), 튕김 없음.
7. **효과음** (`sfx.md`) — 등급표 A★ → A → B 에서 고르되 **역할마다 파일 이름으로 고정**(뜻 확인) · 크기는 2장 표 · 자막/그래픽 등장 프레임에 붙임 · 게이지에는 차오르는 소리 · `rule_check.check_sfx` 통과해야 섞는다 · `ae_scene.mix_sfx`.
8. **확인** — 미리보기에서 단어 시각마다 프레임을 뽑아 모아 보고, ebur128 로 음량·트루피크(−1.5dB 이하)를 잰다. **소리는 귀로 못 들었으면 «못 들었다»고 보고한다.**
9. **납품 3종** — `NN_이름_시작초~.mp4`(또는 `.mov`) · `NN_이름_효과음.xml`(`lec_xml`: 장면 V 트랙 + A2~ 효과음, 시퀀스 시각 그대로) · `NN_이름_미리보기.mp4`(장면 + 사람 + 목소리 + 효과음). **같은 이름으로 제자리 덮어쓰기**(프리미어에 이미 들어가 있다 — 폴더를 지우지 않는다).
10. **점검표** — 9장을 한 줄씩 본다(`checklist.md` A·B·C) → 결과를 보고에 적는다.
11. **피드백 기록** — 사장님 말씀은 **원문 그대로** `기록/작업기록.md` 해당 장면과 `references/feedback-log.md`, 효과음 반응은 `tools/data/예능효과음-실사용.json`(통과/반려) 에. 규칙으로 굳으면 SKILL/checklist 에 **규칙 한 줄 + 점검표 한 줄**(기계로 볼 수 있으면 `rule_check.py` 에도).
12. **작업이 끝나면 항상 납품 폴더를 탐색기로 연다**(`Start-Process explorer.exe "…\한비즈-쇼츠광고\납품"`, 사장님 10-08 «아니 작업 끝나면 항상 폴더 열어 줘»). 묻지 않는다.

## 4. 사장님 상시 규칙 (반려에서 나온 것 — 매 장면 지킨다)

- **자료 파악은 처음부터 끝까지 전부 정독**(10-08 «이제 내가 링크 2개를 주고 자료 2개를 폴더에 넣어서 주소를 줄건데 이제 우리가 어떤작업을 할지 파악해 이거 파악이라는게 진짜 처음붙터 끝까지 다읽고 다 정독해서 해야해 하나라도 빠짐없이 다 대충읽고하면 우리가 10개를 하려는데 7개밖에 모르는 그런상황 절대 일어나면안돼»): 받은 링크·파일은 한 쪽·한 줄·한 장면도 건너뛰지 않는다(영상은 `ref_study` 시트 전부 + 말 전부, 문서는 전 페이지, 표·이미지·각주까지). 읽으면서 **요구 대장**(`기록/작업기록.md` — 요구 하나에 번호 하나, 원문 위치·근거 인용)을 만들고, 다 읽은 뒤 대장을 원문과 한 번 더 대조해 빠진 것을 찾는다. 대장 없이 «파악했다»고 보고하지 않는다.
- **쇼츠 첫 3초는 무조건 사람 얼굴 — 후킹은 자막 밑에**(10-20 7번 «초반 3초는 무조건 사람얼굴나와야해서 자막밑으로 후킹줘야해»): 0~3초엔 화면 전체를 덮는 연출·얼굴 가리는 판 금지. 후킹 그림은 사장님 자막 박스 아래(7번 전신 샷 기준 자막 y 755~818 → 연출 자리 y ≈860~1500, 가슴~무릎)에만. 얼굴 확대·흑백 같은 인물 강조는 함께 써도 된다.
- **완성도 — 덩그러니·일정 속도·정지 금지**(10-21 7번 «덩그러니 건물만있으니까 좀 연출이 별로 … 속도가 너무 일정하고 사진도 움직임이 별로없으니까 고급진 느낌이안나 … 연출방법은 좋은데 완성도가 떨어진다»): 주인공 사물은 빈 배경에 홀로 두지 말고 실제 장소 사진 속에 세운다 · 카메라·움직임은 강약(느림 → 빠름 → 살짝 넘침 → 섬) · 멈춘 사진도 천천히 흐르거나 빛이 훑게. 인물에 흑백·흔들림을 주면 그 위 연출층도 같은 프레임에 같은 효과(10-21 «흑백일때 얘만 멀쩡해서 좀 어색해»).
- **장면 연출 — 한비즈 4번·7번에서 굳은 것(10-20~21, 원문은 feedback-log)**:
  - **고객 건물은 리모델링 후 건물만**(`소재/codex/r7m_night.png`·`r4_uh_iso.png`) — 리모델링 전 붉은 벽돌 아치 건물 금지(«얘 말고 다른 건물써달라고 4번영상에서 요청받은거 기억하지»).
  - **강조는 대본 뜻대로** — «다 같은 … 아니에요» = «=»이 «≠»로 깨짐. ✕·확대는 뜻이 다르다(«x자로 표시하고 저걸 확대하면 이상해»).
  - **말의 결과를 보여 준다 — «45채 사보고» = 건물 사진(과정 사진 아님) · «지었다» = 설계도 → 층이 차오름 → 완공**(«그냥 사진이 올라가는느낌»).
  - **사진 몽타주 4장/초는 뭔지 모름 — 넘긴 장은 작은 카드로 위에 보관**(«위쪽에 작은카드로 보관되는 느낌»). 사진 흐름은 650~800px/초.
  - **흰 니트·밝은 바탕 위 글자는 어두운 알약·상자 안에**(«이게 눈에 안읽히는데»). 흰 윤곽·흰 번쩍은 묻힌다 → 어두운 실루엣·금빛.
  - **좋은/나쁜 대비는 첫눈에 · «나쁜 것»은 새로 그린다 · 같은 고객 다른 편(4번)의 상징(돈다발·+금액·도장) 반복 금지.**
  - **홀로그램 = 남색 그레이딩 위 빛나는 선·점·글자(어두운 상자 UI 아님)** · 먼 건물에도 작은 분석 표지 · 간판·광고판은 추적해서 덮는다.
  - **후기·캡처는 원본 해상도, 본문이 읽히게**(«내용이 초반 3줄이라도 좀 보이게») — 흐림·덮개 금지, 작성자·직원 이름만 가림.
  - **화면 전체 장면은 V1(사람 클립 자리) · 사람 위 층은 V4** · 사장님 전환 Flare/Stretch(`editing-premiere.md` 5-6). 사장님이 다시 저장하시면 그 저장본으로 시각을 다시 맞춘다.
  - **고객 카페 홍보를 겸한다고 하신 경우만 그 고객 이름·로고를 그대로**(«저거 카페홍보겸해서하는거니까 제대로 따라해줘») 다시 그린다 — 다른 업체는 여전히 금지.
- **앞뒤 맥락 먼저**(10-07 «모든 작업은 무조건 앞뒤 맥락 파악해서 연출하라»). 기록에 «앞/뒤 맥락» 줄.
- **구도는 상황에 맞게 — 통과 틀 복붙 금지**(10-07 08 반려 «왜 핸드폰으로 연출했어, 각 상황에 맞게 연출 구도 잡아야지 · 실제 세팅 페이지에서 설정하는 느낌으로»). 휴대폰·비교 판은 기본값이 아니다. **비교 연출은 연달아 쓰지 않는다**.
- **도형 짜깁기 금지**(10-07 06 반려 «도형으로 수준 낮은 짜깁기 원하지 않음») — 그림은 **Codex 이미지·실제 이미지(위키미디어 로고·국기, 녹화 실화면)**. 알약 단계·점 게이지·도형으로 휴대폰/사물 흉내 금지.
- **화면 속 글은 읽히는 예시 글**(회색 줄·블러 금지, «뭘 묻고 뭘 답하는지 글자로») — 그리고 **말 따라 쓰지 않는다**: 말을 뒷받침하는 개념어·구조로(10-08 «심리학적으로 그래요 → 심리학적 요소처럼, 말 따라 하지 말고»). 자막이 이미 말을 보여 준다.
- **인지할 텀 0.6초**(10-07 «연출이 전체적으로 급해서 정신없는 느낌 · 충분히 인지할 텀은 있어야»): 새 요소는 혼자 0.6초 이상, 같은 종류는 묶음으로, 한 문장에 새 요소 2~3개까지. **빈 구간 규칙 때문에 요소를 끼워 넣지 않는다.**
- **효과음은 자연 길이, 단 다음 소리와는 겹치지 않게**(10-07 «효과음 또 짧게 끊기고» + 10-12 «효과음 겹치는부분때문에 듣기싫어» + 10-13 «겹치거나 밀려서 나오는거 조정해서 깔끔하고 자연스럽게») — 잦아드는 데까지(최대 2.5초) 두되, 다음 소리가 오면 그 **들리는 어택 10ms 전에 끝나게 0.2초 감쇠로** 끊는다(~~60ms 페이드~~, 10-19 «효과음이 나오는 도중에 짤리는» 롱폼 10-15 반영). 잘려서 0.15초도 안 남는 타격은 끊지 말고 큐를 옮긴다(둘 다 지키는 길). 소리는 파일 시작이 아니라 **들리는 시각**을 화면에 맞춘다. 빈 구간(2.5초)은 «소리가 실제로 안 나는 시간». 같은 소리 바로 연달아 금지, 번갈아도 3초 안에 같은 파일 3번까지. 게이지·밑줄엔 차오르는 소리. 음정 톤(마림바·실로폰·합성 벨) 금지(정보·신뢰 광고). 청음본·A/B 듣기를 먼저 요청하지 않는다 — 실제 편에 넣어 반응을 받는다. **예외**: 같은 자리 소리를 사장님이 반려하셨는데(«아니야 마음에안들어») 다음 후보가 뚜렷하지 않으면, 그 구간만 후보에 A~F 표지를 붙인 짧은 청음본 하나를 드린다(10-20 4번 «c» → 高速移動). 사진이 주인공인 장면은 훅·휙 대신 셔터·종이 소리(10-21 «훅 휙 이 어울ㄹ지않아»). **들리는 중 잘림 0**(fit_tails WARN 0, 10-21 «효과음이 끊기는 느낌이 너무 많이들어»).
- **비교 장면은 쪽마다 색 하나**(10-07 06 통과 때 «웹사이트랑 인스턴트 같이 비교하는 건 색으로 각각 다름을 강조하면 좋을 것 같아»). 예: 빨강 vs 파랑. 그 외 장면 색은 3색(바탕·글·강조 하나).
- **숫자를 지어내지 않는다** — 말·사장님 확정 문구에 나온 숫자만, 쓰면 그 말의 시각을 기록. 광고 주장 숫자(정책자금·금리·실적)는 공고·랜딩 원문 근거 표가 있어야 하고, 한 문장에 결과 숫자 하나 · 시청자에게 계산시키지 않는다(10-12 «너무 어렵대 … 시청자가 계산하게 시키는거자체가 안읽히는 광고» → `references/copy.md`). 사장님 지시 문구가 보장·대행처럼 들리면(«전부 다 받아드립니다» 등) **고치지 말고 보고에 적어 여쭌다**. **업체명은 ○○, 번호는 010-0000-0000.** 계정 ID·고객명·실제 번호·업체명이 보이는 실자료 금지(그 자리는 Codex 연출 이미지, 녹화본은 주소창·탭·북마크를 자르고, 실제 업체가 보이면 같은 결의 가짜 화면을 다시 그림).
- **사람 자리·자막 자리 비우기**(가로 실측: 사람 0~720×580~1080, 자막 480~1440×900~1080 — 세로는 재서 채움, 6장). 말풍선은 인물 머리 가까이(머리·몸 칸을 따로 막고 흔들림 여유 확인).
- **물어보지 말고 만들어서 보여 준다**(방향이 정해진 뒤엔 선택지를 묻지 않는다 — 사장님은 보고/듣고 반려하신다). 사장님이 «어떻게 하면 좋을까?»처럼 열어 두시면 선택지 질문 대신 **후보 2~3개를 짧게 실제로 만들어 나란히** 보여 드린다(10-13 선택지 질문을 물리시고 «3개다 시도해봐 각각 버전다르게해서 보여줘» · 10-12 «시안나오는대로 빠르게보여줘»). **예외 — 대본은 쓰기 전에 방향을 여쭌다**(10-12 «작업시작하기전에 대본부터짤건데 어떻게ㅉ라지물어보고해»). 기존 작업물은 덮지 말고 따로. 정말 되돌릴 수 없는 일(파일 삭제·외부 발송·prproj 직접 수정)만 확인.
- **납품은 같은 이름 제자리 덮어쓰기, 폴더 지우기·이름 바꾸기 금지**(프리미어에 이미 들어가 있다). **판 나누기 기준**: 사장님 피드백 한 묶음 = 새 판(새 폴더 `…_<N>판_<날짜>`, 영상 파일 이름은 판끼리 같게) · 그 판을 고치는 동안의 지적(소리 정리·후킹 교체·오탈자)은 같은 판에 같은 이름 덮어쓰기 · 문서(대본 PDF) 내용 개편은 `_vN` 새 폴더 + 파일 끝 `_vN`(10-12 «개편사항은 덮어씌우지말고 v2로해서 뽑아줘봐»). 잠긴 파일은 다른 이름으로 두지 말고 남겨 알린다.
- **유료 생성은 장면당 한 건**(후보 비교는 Codex 시작프레임 단계, `count` 2 이상 금지, 발주 전 `get_cost`). 사람 장면 이미지는 항상 «사진기로 찍은 사진» 톤. AI 영상은 구간별 배속 변경 금지(생성 길이로 맞추고 1배속). **원인을 모르면 바꾸는 것을 하나만 두고 시험한다.**
- **영상미**: 등장 4~8프레임 감속·바운스 금지 · 핵심어 하나만 강조색 · 시그니처 모티프 하나 · 보여 줄 게 그림이면 멈춰 두고 글이면 계속 움직임 · 글리치/흔들기는 한 편에 한 번 · 북엔드(`motion-graphics.md` 6장, 학습분).
- **규칙 누락 방지**: 시작 전·장면마다·납품 직전에 문서를 다시 연다(09-28 «규칙 누락 현상 심함»). 새 피드백은 규칙 한 줄 + 점검표 한 줄을 바로 추가.
- **정한 건 즉시 파일로** — 대화에서 정한 것은 그 자리에 기록(`기록/작업기록.md`, 이 스킬). 대화는 요약되면 사라진다.
- **말풍선·캐릭터**: 꼬리 끝은 머리 위 16px 에서 멈추고 효과선은 머리 반지름 바깥만(10-08 18 반려 «말풍선 뾰족한 거 위치가 캐릭터 머리 위에 겹치지 않게 살짝 떨어지게»). 대사를 «» 따옴표 카드로 넣지 않고, 밋밋한 아이콘 카드 대신 캐릭터 표정·말풍선(19 반려 «차라리 캐릭터 눈으로 귀엽게라도 표현하던지 · «» 이렇게 대본 넣는 거 별로 안 이뻐»). 띄운 확대 창과 그림 속 모니터를 선으로 잇지 않는다(21 «굳이 이어 주지 않아도…»).
- **판·카드는 구멍 없이**: 알파 255, 모서리 반경 카드 14 · 이름표·뱃지 12 — 반투명(190~238)·큰 반경(34)은 뒤 영상이 비친다(09-22 디자인 반려, `motion-graphics.md` 9장).
- **이미지는 레퍼런스를 보고, 글자는 AI 에 맡기지 않는다**: 레퍼런스 없이 상상한 이미지는 «경험상 다 별로였다», 한글·지명·역명은 바탕만 생성하고 글자는 PIL+Pretendard(`design-paths.md` 맨 위).
- **글자·UI·숫자·로고가 주인공인 컷은 렌더러(폰트)가 그린다 — 영상 생성 모델에 맡기지 않는다**(10-08 학습: 영상 모델이 «비타민B»를 «에터민B»로, «Complex»를 «Corxplex»로 그림, `references/study/2d-mg-newtake.md`). 장면 스펙에 화면 글 목록(EXACT STRINGS)을 두고 결과와 대조. 글자가 사람·제품에 가려지지 않게.
- **말 없는 모션그래픽 릴(T4)만 박 격자**(사장님 10-08 «화려한 모션그래픽은 그냥 이런식으로 tts없이»): 1마디 = 1장면, 같은 종류 4칸 몽타주는 1박(≈0.5초)씩 묶음 허용 — 낱개 새 요소는 여전히 0.6초. 장면 안 3색, 편 팔레트는 브랜드 색. 설명형은 단어 시각 + **자막 A2(회색 불투명 띠)**(10-08 «a스타일인데 테두리색 살짝 현재보다 좀더 회색빛돌게하고 테두리크기를 좀 줄여줘»).
- **레퍼런스는 짚은 요소만** — 팔레트·비율·구간·동작을 장면 스펙으로 옮기고, 통째 모사·타사 이미지를 생성 입력으로 넣지 않는다.
- **기법 고르기는 `references/techniques.md` 표에서** — 기법마다 언제·본보기 코드·통과/반려 요점이 한 줄씩 있다.
- 말이 화면과 소리 양쪽에 걸리면(예: «연필») 직전 보고에서 그 이름을 어디에 썼는지부터 본다.
- **두 세션이 같은 저장소에서 돌 때**(10-12 «이 세션은 지금 작업중인 다른세션이랑 독립적으로 병목이나 충돌현상없이 별도 폴더를 하나 만들어서 진행한다»): 둘째 세션은 `병행작업/`(기록·납품·소재·tools·_tmp 따로, 규칙은 «스킬 반영 대기» 표 → 겹치지 않을 때 스킬로 이관) · 무거운 렌더 `--workers 1~2` · Codex 는 세션끼리도 한 번에 하나, **저장소 루트에서** 부르고 프롬프트에 «후처리 명령 금지»(Windows `convert.exe` 를 잡은 적 있음) · 두 기록이 다르면 원문(공고·계약·사장님 말씀)이 이긴다.

| «같은 전환 연속 금지»(분양) vs «시그니처 모티프 하나를 반복»(후킹 영상미 2) | 분양: 같은 전환을 바로 연달아 쓰지 말라 | 후킹: 한 편의 문법을 하나로 — 연달아 같은 동작이 붙지 않게 사이에 다른 움직임 |
| 청음본·A/B 듣기 요청 금지 | 모든 건(10-02) | 실제 편에 넣고 반응을 `예능효과음-실사용.json` 에 · 예외: 같은 자리 반려 뒤 후보가 흐리면 그 구간 짧은 청음본 하나(10-20) |
**한비즈 쇼츠가 위 어느 쪽인지는 건마다 사장님이 정한다(미확인) — 시작할 때 이 표로 범위부터 정하고 `기록/작업기록.md` 에 적는다.**
(원본: 문서지도.md 4장)

## 6. 가로 강의 장면에서 배운 규칙 → 세로 쇼츠(1080×1920)에 옮길 때 바꿀 점

수치 대부분이 **가로 1920×1080 강의 시퀀스**에서 잰 것이다. **세로 수치를 지어내지 않는다.** 첫 작업 때 사장님 편집(`tools/read_prproj.py`)과 정지 화면에서 재서 아래 «재서 채울 칸»을 채우고, 채운 값은 이 표와 `motion-graphics.md` 5장에 같이 적는다.

| 항목 | 가로 강의 장면 값(근거 있음) | 세로 쇼츠 값 |
|---|---|---|
| 시퀀스 크기·fps | 1920×1080 · 59.94 | **한비즈 4번·7번 = 900×1600 · 59.94**(사장님 프리미어 실측 10-19~21) — 장면도 900×1600 · 59.94 로 렌더한다(`지시작업/tools/scene_kit.py`). 메타v2(10-14)는 1080×1920. 분양 쇼츠는 29.97 |
| 사람 자리 | 왼쪽 아래 0~720×580~1080 (V2 30%, x 0.073~0.093) | 7번 전신 앉은 샷: V1 61.08% · 위치 0.53:0.549 · 얼굴 y 400~680 · 흰 니트(그 위 글자는 어두운 알약) · 옆모습 카메라 멀티7 49%(얼굴 x 300~500) |
| 자막 자리 | 480~1440×900~1080 | **7번 V2 자막 y 755~818 · 4번 y 900~950** → 연출 자리 = 자막 밑 y ≈860~1500 · **읽혀야 할 글자는 y 1300 위**(쇼츠 아래 UI 가림, 9-2f) (옛 참고 — 분양 쇼츠: 자막 PNG 를 «가운데 아래 y=1150»(≈0.60H)에 둔 XML 이 있었고, 애펙 장표 장면은 자막 위쪽 (540,640)·상자 1010×860 에 관심 영역을 놓았다 — 확정 아님) |
| 반반 판 | 사람 x 960→480, 판 기준점 x 900, 판 크기 1100,96~1890,836 | ☐ **세로에서 좌우 반반이 성립하는지부터** 사장님과 정한다 |
| 화면 요소 최소 크기 | 영상에서 0.47배로 줄어도 읽히게 크고 짧게(휴대폰 사진 속 글) | ☐ 세로 시청(휴대폰) 기준으로 재서 |
| 효과음 크기 | 목소리 대비 −2/−3/−8, 파일별 구울 값표, 목소리 A1 +7dB | ☐ 세로 쇼츠 편집의 클립 볼륨으로 재서 `sfx.FILE_DB` 갱신 |
| 컷·전환 리듬 | (분양 쇼츠 실측) 컷 평균 2.3초 · 전환 0.25~0.35초 · 자료 약 2초 · 음성 1.15배 | 분양 쇼츠 값은 세로에서 잰 것 — 한비즈 쇼츠에서 같은지 ☐ |
| 가로 소재 리프레임 | (분양 쇼츠) 스케일 52.08% 주력, 위치 중앙 | ☐ |
| 카메라 기본 틀 | 960,540 (CAM 식 `view − 960/540`) | `W/2, H/2` 로 바꾼다(`ae_scene.W,H`) |
| 인지할 텀 0.6초 · 반 박 8프레임 · 등장 4~8프레임 | 시간 기준 | 같은 값을 쓰되 세로 쇼츠 속도감에 맞는지 ☐ |
| 흰 플래시 | 컷 앞 2프레임(0.05초 @30fps) | fps 에 맞춰 환산 |
| 자막 스타일 | 레퍼런스8: 페이드+0.94→1.0 확대 3~4프레임, 머무는 동안 1.0→1.02, 팝 130→100 0.216초 | 세로 쇼츠 자막 위치·크기 ☐ |
